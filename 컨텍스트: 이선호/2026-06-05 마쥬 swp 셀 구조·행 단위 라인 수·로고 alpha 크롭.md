### A. swp 셀 「행 단위 렌더 라인 수 일치」 룰 강화 ✅

이전 룰 (frame height 26 + BOTTOM 정렬)만으론 같은 행 내 한 셀이 2행이고 다른 셀이 1행이면 시각적으로 어긋남이 보였다. → **렌더 라인 수까지 명시적으로 일치**시키도록 자동화 절차 6단계로 확장.

**핵심**: needs2Lines row 안에 자동 wrap 안 되는 짧은 셀(예: `Suit trousers`)은 `\n`을 명시 삽입해 강제 2행화. 끊는 위치는 「줄바꿈 위치」 룰 (특징/카테고리 경계, `with` 접속사 앞, 단어 2개뿐이면 단일 공백).

**적용 사례 (03-swp2 row 0 / 03-swp3 row 0·1)**:
- `Suit trousers` → `Suit\ntrousers`
- `Cotton skirt shorts` → `Cotton skirt\nshorts`
- `Linen Blended Short` → `Linen Blended\nShort`

needs2Lines 판정 트리거도 확장: `1행 폭 > 임계값` **OR** `\n 포함` **OR** `with 등 접속사 포함`.

→ 룰: [[CLAUDE]] line 58 + [[2-4. 화보·상품]] 「줄바꿈 위치 (자연스러운 끊기 우선)」 + 「자동화 구현 (임계값 = 텍스트 박스 width)」 9단계

### B. swp 셀 구조 재정의 (1차 오류 → 사용자 피드백 → 정정) ⚠️

사용자가 "셀 내 모든 항목 좌우 중앙 + 텍스트 2개 오토레이아웃 + bottom 정렬" 요청. **1차 시도(오답)**: 셀 자체를 VERTICAL AL (`primaryAxis = SPACE_BETWEEN`, `counterAxis = CENTER`)로 만들고 그 안에 [image rect, text wrapper] 배치. 사용자 피드백: "오토레이아웃은 텍스트 박스 2개만 묶어달라는 말이었어. 셀 자체에 걸면 안돼. 상품마다 높이가 달라서 수동 조정, 같은 행에 있는 상품 이미지끼리는 상하 중앙 정렬해야 해서 그래"

**정답 구조**:
```
cell (FRAME, layoutMode: NONE)              ← 셀은 절대 좌표 (수동 드래그)
├─ image RECTANGLE (절대 좌표)
│      x = (cell.w − rect.w) / 2
│      y = ((wrapper.y − 10) − rect.h) / 2   ← 가용 영역 상하 중앙 (기본값, 사용자 수동 조정 가능)
└─ text wrapper FRAME (절대 좌표, VERTICAL hug AL)
       primaryAxis: MAX, counterAxis: CENTER
       x = (cell.w − wrapper.w) / 2
       y = cell.h − wrapper.h
       children: nameText + priceText
```

**왜 셀에 AL 걸면 안 되는지** (반드시 기억): 같은 행 안 상품들의 누끼 키가 다 다르므로, image RECT의 vertical y를 사용자가 수동으로 미세 조정해야 한다. 셀에 AL를 걸면 구조적으로 고정되어 드래그가 막힌다. 같은 행 wrapper.h가 동일하면(needs2Lines row → 모두 39) **가용 영역도 동일** → 자동 계산만으로도 행 단위 vertical-center 정렬은 자연 보장.

→ 룰: [[CLAUDE]] line 58 위 「swp 셀 구조」 + [[2-4. 화보·상품]] 「셀 구조 — 절대 좌표 + 텍스트 wrapper만 auto-layout」

**적용 범위**: 활성 swp 4개 페이지의 23개 셀 전부.

### D. 로고 alpha bbox 크롭 (옵션 B 채택) ✅

사용자 지적: "로고가 상하 여백이 덜 크롭됐어"

**원인 진단**: 04-BG/04-swp1이 공유하는 로고 PNG (hash `964ce1f1ea60c983aeecb44c7fe9f16cf8ab4c3f`, 842×596)에 상하 22% / 좌우 6% alpha 여백이 박혀 있음. 03-BG 로고 (hash `a0378f95832a31290cd27032f5a80aafb9dd19df`)도 동일 정도의 여백.

**검증 방법** (반드시 기억): 임시 RECT(소스 원본 사이즈 842×596)에 magenta `#FF00FF` backing rect를 깐 뒤 `screenshot({ scale: 12 })`로 캡처. magenta 노출 영역 = alpha 여백. 정상 로고는 magenta가 거의 안 보인다.

**두 가지 fix 옵션 + 선택 기준**:
- **A. 소스 PNG 크롭 후 재업로드** (정공법): `getBytesAsync()` → PIL `getbbox()+crop()` → `figma.createImage()` 로 새 hash → 모든 로고 RECT의 fill 교체.
- **B. `scaleMode: "CROP"` + `imageTransform`으로 가시 영역만 샘플링** (소스 그대로): `imageTransform = [[x_scale, 0, x_offset], [0, y_scale, y_offset]]`. rect 비율도 가시 콘텐츠 비율에 맞춰 면적 보존 리사이즈.

**오늘 옵션 B 채택 이유**:
1. 같은 hash(`964ce1f1`)를 04-BG·04-swp1 두 페이지가 공유 → 소스 한 번 정의로 일괄 처리 효율적
2. **Write 도구/Bash heredoc가 ~16KB base64를 반복적으로 truncate** (maje-04: 12,353 → 8,334 또는 12,122바이트로 손실, PIL "broken PNG" 에러). 옵션 A 진행 도중 사용자가 "지금 작업 오래 걸리는 이유가 뭐야?" 질문 → 옵션 B로 전환 결정

**적용 파라미터** (두 PNG 공통):
- 가시 bbox: y=[0.22, 0.82], x=[0.06, 0.96]
- `imageTransform = [[0.90, 0, 0.06], [0, 0.60, 0.22]]`
- 가시 콘텐츠 비율 **2.12** (가로/세로)
- rect 면적 보존 리사이즈: `w = √(S·2.12)`, `h = √(S/2.12)`

## 이번 세션 핵심 교훈 (다음 세션을 위해 명심)

1. **셀 = NONE, 텍스트만 wrapper AL** — "오토레이아웃 걸어줘"라는 사용자 요청에 셀까지 AL로 묶지 말 것. 누끼 키 차이가 큰 swp 셀은 image RECT의 y를 수동 드래그할 수 있어야 한다.
2. **「렌더 라인 수 일치」와 「frame height 26 일치」는 다르다** — BOTTOM 정렬로 가격 baseline은 맞아도 텍스트 라인 수가 다르면 시각적으로 어긋남. needs2Lines row면 모든 셀에 `\n` 강제 삽입.
3. **로고 alpha 검증은 magenta backing 트릭** — `screenshot({scale:12})` 으로 magenta 노출 영역 = alpha 여백. 시각적 측정만으로 충분히 정확.
4. **Write/Bash heredoc는 ~16KB 이상 binary base64를 truncate한다** — 옵션 A(PIL crop + 재업로드)는 분할 청크 합치기 필요. 같은 hash 공유 시 옵션 B(scaleMode CROP + imageTransform)가 압도적으로 효율.
5. **세션 중 Figma node ID가 바뀔 수 있다** — 사용자가 작업 영역을 옮기면 frame이 새 인스턴스로 재생성. 시작 시 항상 `findAll(name)`으로 재탐색.
