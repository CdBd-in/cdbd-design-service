## 🔬 이번 세션에서 실측한 CdBd 규칙 (문서 반영 후보)

### 1. `multiCard.ratio` 는 **20~80 클램프**
`ratio: 92`로 PATCH해도 데이터엔 들어가지만 **렌더러가 80으로 잘라낸다.** 좌우 비율을 80:20보다 더 극단으로 못 준다.
→ 작은 아이콘을 우측 끝에 붙이려면 **이미지 자체에 투명 패딩**을 넣어 해결한다.
- 콘텐츠 폭 332 − gap 12 = 320 → 20% = **64px**가 우측 셀 최소 폭
- `07-call-pad.png` = 64×24@3배(192×72) 캔버스에 24px 원형 아이콘을 **우측 정렬** → `width 100%`로 렌더하면 아이콘이 카드 우측 여백(24px)에 정확히 flush
- ⛔ `justifyContent: flex-end` 등 UI 미검증 키 shotgun 금지 (이 방식으로 우회함)

### 2. **텍스트 셀 링크 = lexical `link` 노드가 본체** (`linkButton`만으론 클릭 안 됨)
`multiCard.items[].linkButton`만 넣으면 **데이터엔 들어가지만 뷰어가 `<a>`로 감싸지 않아 클릭 불가**(이미지 셀은 `linkButton`만으로 `<button>` 래핑됨 — 동작이 다름).
계정 내 UI 제작본(에디터 **5306**) 실측 = 텍스트 링크는 lexical AST에 **`type:"link"` 노드**로 저장되고 `linkButton`은 디자인 보드 표시용으로 **함께** 존재.

```jsonc
// custom-paragraph.children[0]
{
  "children": [ {…text node…} ],
  "type": "link", "version": 1,
  "direction": "ltr", "format": "", "indent": 0,
  "textFormat": <상속>, "textStyle": <상속>,
  "rel": "noreferrer", "target": null, "title": null,
  "url": "tel:0234678974"        // mailto: / https:// 도 동일
}
```
- `linkButton` 정식(UI 제작본) 형태: `{"link":{"href":"","openNewTab":false},"type":"call","phone":{"phone":"…"}}`
- **밑줄은 별도로 끌 필요 없음** — CdBd 뷰어는 링크에 `text-decoration`을 붙이지 않는다. 실측 `text-decoration-line: none`, 계정 400개 에디터 스캔에서 `text-decoration` 사용 0건 / `underline` 값은 전부 `false`.

### 3. 인증 복구 = **브라우저 state 경유** (refresh_token 만료 시)

7페이지 1번 행을 사용자가 직접 손보고 "나머지도 동일하게" 요청 → **1번 행 값을 읽어 18개 행에 복제**하는 방식으로 처리. 그 외 사용자 수정분은 diff로 확인 후 **보존**.

| 사용자 수정 (보존) | 값 |
|---|---|
| 로고 카드 외부여백 | `0px 0px 0px 8px` → `40px 0px 0px 8px` |
| 헤더 divider 여백 | `32px 24px` → `32px 24px 13px` |
| 타이틀 줄간격 | 1.4 → 1.5 |
| 마지막 행 여백 | `0px 24px 40px` → `0px 24px` |
| 맨 끝 마감 divider 카드 | 신규 추가 (41번째, `13px 24px 40px`) |

| 복제 적용 (18행) | 값 |
|---|---|
| `multiCard.ratio` | 80 → **75** |
| 매장명 | 13px → **15px** |
| 주소 | 11px `0.45` → **13px `0.6`** |
| 줄간격 | 1.4 → **1.6** |

> 💡 **패턴화**: 이 사용자는 **1번 항목만 UI로 다듬고 "나머지 동일하게"** 를 요청하는 방식을 선호한다. 대량 반복 카드는 (1) 현재 상태 GET → (2) 기준 항목 값 읽기 → (3) 나머지에 그 값만 복제 → (4) **PATCH 전 이전 저장본과 diff 떠서 사용자 수정분 확인** 순서로 처리할 것.
