## Figma MCP 기술 메모

다음 세션에서 같은 실수를 피하기 위한 주의사항.

1. **upload_assets로 imageHash 얻기**: nodeId 지정 + count=1 + scaleMode FILL → 반환 URL에 raw bytes POST → 응답 JSON의 `imageHash`를 추출. (각 이미지마다 별도 upload_assets 호출이 필요 — count>1에선 nodeId 지정 불가.)
2. **화보 rect는 항상 자식 RECT**: `frame.fills` 직접 적용 금지. `figma.createRectangle()` + `rect.fills = [{type:'IMAGE', scaleMode:'FILL', imageHash:...}]` + `frame.insertChild(0, rect)` 순서.
3. **rect 위치 좌표는 부모에 종속**: `frame.insertChild(0, rect)` 호출 후 rect.x/y는 frame 기준으로 재설정해야 함. 다른 부모에서 옮긴 직후엔 좌표가 어긋남.
4. **page context는 호출마다 리셋**: 작업 페이지가 default가 아니면 `await figma.setCurrentPageAsync(page)`를 매 use_figma 호출 첫 줄에 둘 것.
5. **TEXT fill 변경 시 폰트 로드 선행**: `getStyledTextSegments(['fontName'])` → `await loadFontAsync(seg.fontName)` 후에만 fills 변경 가능 (canonical recipe).
6. **Group 리사이즈는 자식까지 스케일**: `group.resize(w, h)` 호출 시 자식 노드들이 비례 축소·확대됨. PRENDANG 로고도 이 방식으로 크기 조정.
7. **LAYER_BLUR effect**: 블러 BG 구현 시 `rect.effects = [{type:'LAYER_BLUR', radius:30, visible:true}]`. BG rect는 frame보다 충분히 크게(예: 760×950) 만들어 가장자리 페이드 방지.
8. **template 노드 ID 검색**: `findAllWithCriteria({ types:['FRAME','COMPONENT'] })` + width/height 필터로 380×580 또는 340×440 매칭 노드를 찾아 reference 사용. parentName에 `01-thick frame` 등 label이 들어있어 식별 용이.

## Figma MCP 기술 메모 (재개 세션 추가)

9. **JPEG SOF marker 파싱**: PNG IHDR(offset 16/20)와 달리 Figma upload된 JPEG은 SOF0/SOF2(0xFF C0/C2) 마커에서 dim 추출. 알고리즘: 0xFF marker → skip padding → if SOF marker → height at +5/+6, width at +7/+8 (big endian). pure JS로 구현 가능.
10. **PNG zlib 디코딩 inline**: pako_inflate.min.js (21KB)를 `use_figma` code에 임베드 → IDAT chunk inflate → PNG 스캔라인 필터 디코딩(Up/Sub/Average/Paeth) → alpha 채널 추출 → bbox 계산. 외부 도구·context 부담 없이 plugin 내부 완결.
11. **scaleMode 'CROP' + imageTransform**: `[[a,c,tx],[b,d,ty]]` 2×3 매트릭스 = RECT uv (0~1) → source uv (0~1) 매핑. bbox crop 표현: `[[bw, 0, bx0], [0, bh, by0]]` (bw=bbox 너비, bx0=bbox 좌상단 x in source). **identity transform `[[1,0,0],[0,1,0]]`** + scaleMode CROP은 RECT aspect ≠ source aspect 시 source가 stretch 됨 → 원본 비율 깨짐. **aspect 보존하려면 scaleMode FILL** (RECT aspect = source aspect 필수).
12. **plugin sandbox에서 raw bytes return 한계**: 단일 hash의 PNG bytes (≈3MB) base64화 시 ≈4MB 문자열 — context 폭주. **대안**: ① exportAsync로 작은 PNG (256w 등) → 작은 base64. ② plugin 내부에서 PNG 디코딩 + bbox 계산 후 작은 수치만 return. ③ 별도 Agent에 작업 위임 (context 격리).
13. **Agent 격리 전략**: 23개 hash 처리처럼 context 부담 큰 작업은 단일 Agent에 위임 (서브에이전트 context = 별개). 메인은 최종 요약(IDs, summary table)만 받음.
14. **상품 cell 텍스트 줄바꿈** (swp 패턴): `n.textAutoResize = 'WIDTH_AND_HEIGHT'` 로 natural width 측정 → cell width 초과 시 ` - ` 위치에서 강제 줄바꿈 (`replace(' - ', '\n- ')`) + `textAutoResize = 'HEIGHT'` + `resize(maxW, ...)`. 동일 상품 다색상은 1행 고정.
15. **가격 천단위 콤마**: `toLocaleString()`이 Figma JS에서 작동 안 함 → 정규식 사용 `price.toString().replace(/\B(?=(\d{3})+(?!\d))/g, ',')`.
