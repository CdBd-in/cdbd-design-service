## 1. 개요

신세계 와인앤모어는 매월 **모바일 카달로그(행사 리스트)**를 CdBd 단일페이지로 제작한다.
각 "행사"는 `cdbd.in/wmevent{N}` 슬러그의 CdBd 에디터 1개에 대응한다.
작업은 대개 **엑셀(제작 요청서)의 상품 데이터로 기존 이벤트 페이지의 상품 카드를 교체**하는 것.

- 페이지 타입: `single` (멀티페이지 아님)
- 상품 1개 = **이미지 블록 + 텍스트(상품 정보) 블록 + 구분선(여백) 블록** 3종 세트 반복
- 상단: 헤더(행사명) + 기간 + (선택) NEW뱃지/추가문구/브랜드소개
- 하단: 홈으로 돌아가기 링크 + 음주 경고 문구

## 4. ⭐ 자동화 방법 (Supabase 직접 PATCH — 검증된 유일 정석)

> **왜 이 방법인가**: Playwright는 Google OAuth 로그인 벽에 막히고, gstack 브라우저는 이 PC에 미설치.
> CLAUDE.md가 권장하는 **Supabase 직접 자동화**가 유일하게 작동. (콘솔 JS 주입도 자동저장 race로 실패)

### 4-0. 인증 재료
- **Supabase 프로젝트**: `jzwrixxevnfogfjzgaqz`
- **anon key (공개·프론트엔드 번들에 있음)**: cdbd.in `/_next/static/chunks/5784-*.js` 등에서 `role:anon` JWT 추출
  ```bash
  curl -s https://www.cdbd.in/ -o home.html
  for f in $(grep -oE '/_next/static/[^"]*\.js' home.html | sort -u); do
    curl -s "https://www.cdbd.in$f" | grep -oE 'eyJ[A-Za-z0-9_-]+\.eyJ[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+' | grep -m1 anon; done
  # 실측값(2026-07): eyJ...role":"anon"...  ref=jzwrixxevnfogfjzgaqz  exp=2046
  ```
- **access_token**: 사용자 브라우저 쿠키 `sb-jzwrixxevnfogfjzgaqz-auth-token.0/.1` 안의 `refresh_token`으로 갱신
  ```
  POST https://jzwrixxevnfogfjzgaqz.supabase.co/auth/v1/token?grant_type=refresh_token
  headers: apikey=<anon>, Content-Type: application/json
  body: {"refresh_token":"<쿠키에서 추출>"}
  → 응답 access_token (1시간 만료, refresh_token으로 재발급)
  ```
  - ⚠️ 쿠키 `.0` base64 청크는 `.1`과 이어붙여야 완전 디코드되지만, `refresh_token`/`access_token` 값은 `.0` 안에서 정규식(`"refresh_token":"([^"]+)"`)으로 바로 추출 가능
  - ⚠️ 헬퍼 `~/.config/cdbd/auth.py`가 **이 PC엔 없음**. 있으면 `get_credentials()` 사용.

### 4-1. 이미지 교체/추가 = 반드시 이미지 라이브러리 경유 (3-call)
`image_modal` 테이블(이 user의 row `id=121`, `images[]` 배열)에 등록해야 사용자가 UI 「내 이미지」에서 관리 가능.
1. **storage 업로드**: `POST /storage/v1/object/user_image/{uid}/{YYYYMMDDHHMMSS}_{rnd12}.png` (Content-Type image/png, x-upsert true, body=파일바이트)
2. **서명 URL**: `POST /storage/v1/object/sign/user_image/{path}` body `{"expiresIn":946080000}` → `signedURL` 앞에 `{SB}/storage/v1` 붙임
3. **라이브러리 PATCH**: `image_modal.images[]` GET → 신규 entry를 **배열 앞에** append → PATCH
   - entry 스키마: `{id(8-4-4-4-12 랜덤), url(signed), name(확장자제거), path, size(str), type:"png", pexels:null, user_id, folder_id:null, created_at(ISO), deleted_at:null, is_deleted:false, resolution:"W*H", is_bookmarked:false}`
- 반환 signed URL을 **이미지 블록의 `content`**(문자열)에 그대로 넣음
- 라이브러리에 이미 있으면 재업로드 말고 재사용(upload_if_missing) — 이번엔 8종 모두 없어서 신규 업로드

### 4-2. 블록 교체 + editor PATCH
1. `GET /rest/v1/editor?id=eq.{eid}` → 전체 row 확보(**다른 블록·설정 보존**)
2. Python으로 `blocks` 배열 조립 (상품 세트 삭제/추가/교체)
3. `PATCH /rest/v1/editor?id=eq.{eid}` body `{"blocks": [...]}` (Prefer: return=minimal → 204)
4. `GET` 재검증

### 4-3. ⚠️ 필수 규칙
- **PATCH 전 사용자에게 에디터 탭 완전 close 요청** → 안 그러면 client 자동저장이 PATCH를 덮어씀 (새로고침 부족, 완전 close)
- **게시(publish)는 하지 않음** — 초안(`editor`)만 수정. 라이브 페이지는 게시 전까지 옛 내용 유지. 게시는 사용자 위임/명시 요청 시에만.
- 콘텐츠 수정 시 **디자인 속성(폰트·크기·컬러·줄간격) 보존, 텍스트/이미지 내용만 교체**. 줄바꿈 재배치는 허용.
