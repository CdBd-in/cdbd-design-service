### ⚠️ 헤더 폭 계산 규칙 (중요)
헤더 PNG는 **캔버스 폭이 제각각(584 / 660 / 700)** 이라 `width %`를 고정하면 페이지마다 글자 크기가 달라 보인다.
기존 02~04 페이지 기준 배율 `s = 180 / 660 = 0.2727` 을 유지하도록 캔버스별로 환산:

```
width% = round( canvas_px × (180/660) / 340 × 100 )
  584px → 47%      660px → 53%      700px → 56%
```
(패딩 박스 = 380 − 좌우 padding 20×2 = **340px**)

### 헤더 PNG 제작 스펙 (실측·재현 검증 완료)
- 캔버스 높이 **104px** 고정, 배경 투명 (빨강은 카드 `style.background`로)
- 아이콘: 좌측 `x 5~97`(약 92×92) 영역에 FIT
- 타이틀: **Binggrae Bold, size 80px, letterSpacing −2%, 흰색**, 글자 bbox 좌측 = **x 139**, 상단 = **y 14**
- 로컬 폰트 `/Users/mustard/Library/Fonts/Binggrae-Bold.ttf` 설치되어 있음 → PIL로 렌더 가능
  (⚠️ Figma MCP에서는 Binggrae 로드 불가할 수 있으므로 **이미지로 처리**하는 것이 정답)
- 검증법: 기존 자산과 같은 문자열을 size 80으로 렌더해 bbox를 비교 → `기타치즈` 300×70 vs 자산 301×70 (일치)

## 7. 실무 노트 (이번에 확인/겪은 것)

### Figma
- 섹션 `42:151`의 **07~10 헤더 title 프레임엔 아이콘이 없다** (05·06만 있음).
  → 사용자가 별도로 만든 헤더 PNG에는 아이콘이 포함되어 있으므로 그쪽이 정답.
- 05 페이지의 타이틀2·타이틀3 아래에 **구분선이 2개 겹쳐 있음**(14px 간격) — 작업 아티팩트로 판단해 1개만 구현.
- `get_metadata` 응답이 20KB에서 truncate됨 → 페이지를 나눠서 read-only `use_figma`로 덤프하는 편이 안전.

### CdBd 자동화
- `editor` GET이 **stale replica**를 반환할 수 있다 (4페이지 vs 10페이지). **쓰기 직전 반드시 재GET** 후 그 위에서 수정할 것.
- `updated_at`이 갱신되지 않는 쓰기 경로가 존재 → 동시 편집 판정 지표로 `updated_at`만 믿으면 안 됨. **내용 자체를 비교**할 것.
- 이미지 업로드는 `~/.config/cdbd/image_library.py`의 `upload_if_missing()` 사용 (storage POST → sign → `image_modal.images[]` PATCH 3-call 캡슐화).
- 인증은 `~/.config/cdbd/auth.py`의 `get_credentials()` — refresh_token 자동 갱신. 사용자에게 토큰 요청 불필요.
- **브라우저 세션(`.gstack/browse-states/cdbd.json`)은 만료 상태.** 브라우저 작업이 필요하면 1회 재로그인 후 `$B state save cdbd` 필요.
  (이번 세션은 전부 REST 자동화로 처리 — 비밀번호 미사용·미저장)
