## 화보 이미지 배치 (⚠️ 가장 중요 — 모든 화보 페이지 공통)

- **⚠️ 화보 이미지는 「프레임 fill」이 아니라 「별도 자식 RECTANGLE 레이어」로 가장 아래(z-index 0)에 배치한다.** 부모 프레임 `clipsContent = true`로 설정하고, 자식 RECTANGLE의 사이즈·위치를 자유롭게 조정해 노출 영역을 정한다.
  - ❌ Anti-pattern: `frame.fills = [{type:'IMAGE', ...}]` — 프레임 fill로 직접 적용 → 사이즈·위치 조정이 불가능하고 imageTransform/CROP에 의존해야 함.
  - ✅ Correct pattern: `const rect = figma.createRectangle(); rect.fills = [{type:'IMAGE', scaleMode:'FILL', imageHash:...}]; frame.insertChild(0, rect)` — 자식 레이어로 추가, x/y/width/height 자유 조정.
- **모든 화보 이미지는 절대 크롭하지 않는다.** 이미지는 **원본 비율을 유지**한다.
- 화보 프레임에는 **clip contents**가 적용되어 있으므로, 노출 영역은 **이미지(자식 rect)의 위치(필요 시 크기)만 조정**해 정한다. (이미지 자체를 잘라내지 않음)
  - Figma에서는 **이미지를 프레임 크기에 맞춰 줄이는 scale-to-fill 크롭이 아니라, 원본 비율 그대로 두고 위치·배율만 조정**해 프레임 clip이 잘라내게 한다.
  - 자식 rect는 **원본 비율의 사이즈**로 만들고, 프레임 외부로 overflow되는 부분은 clip된다(예: 380×580 프레임에 1440×1890 화보 → 442×580 rect at (-31, 0) FILL identity → 좌우 31px씩 clip).
- 위치를 정할 때 **모델 얼굴, 상품 정보에 포함된 착장 상품 영역 등 중요한 부분이 잘리지 않도록** 한다.
- **모델이 한쪽으로 심하게 치우친 컷이 아니면, 웬만하면 모델이 노출 영역의 정중앙(좌우·상하)에 오도록** 배치한다.
- **풀샷 원본인 경우 머리·발 모두 표시한다.** 머리 상단 여백이 지나치게 넓거나 좁지 않게 자식 rect 사이즈/위치 조정.
- **프레임 비율과 맞지 않아 화보로 다 채우기 어려우면**: 크롭·왜곡 대신 **Figma AI 배경 늘림(확장)**으로 여백을 채운다. (배경 작업은 Figma AI 사용 — 에디터에서 적용)
- **blur BG에서는 배경 화보(자식 rect)를 더 크게 확대**해 배경감을 살린다. (선명한 화보 카드/내부 프레임은 별도)
- 적용 범위: **OG 이미지 / 시안·초안 / 01·02·03 등 모든 화보 페이지 공통.**

### 위치·사이즈 결정 트리 (샷 타입 × 좌우 위치 × 자세)

> 모델이 노출 영역에 어떻게 배치되어야 하는지 판단하는 의사결정 트리. 위 원칙(원본 비율 유지·중요 부분 보호)을 만족시키기 위한 **구체적 판단 기준**.

```
화보 이미지 위치/사이즈 결정
│
├── ① 샷 타입은?
│   │
│   ├── 풀샷 (머리~발끝, 상하 여백 있음)
│   │   │
│   │   └── ② 모델이 좌우 어디에 있나?
│   │       │
│   │       ├── 좌우 중앙 (여백비 ≤ 4:6)
│   │       │   └→ [규칙 A] 모델 정중앙 배치
│   │       │      • 상단 여백 ≥ 40
│   │       │      • 하단 여백 ≥ 20
│   │       │      (380×580 프레임 기준)
│   │       │
│   │       └── 좌우 치우침 (여백비 > 4:6)
│   │           └→ [규칙 B] 사이즈 키워서 모델 몸을 좌우 중앙으로
│   │              • 크롭 필요 시 다리쪽만 (머리쪽 X)
│   │
│   ├── 웨이스트~니샷 (허리~무릎 잘림, 머리 위 여백 있음)
│   │   └→ [규칙 C] 모델 정중앙 배치 (위치·자세 무관)
│   │      • 머리 상단 여백 ≥ 40
│   │
│   └── 바스트샷 (가슴~허리, 상하 여백 없음·머리 일부 잘림)
│       └→ [규칙 D] 사이즈 키워서 좌우 중앙 (위치·자세 무관)
│          • 머리 잘리지 않게
│
└── ③ "좌우 중앙"의 정의 (모든 규칙 공통, 자세에 따라 기준선이 다름)
    │
    ├── 정면 보고 서있음 / 앉아있음
    │   └→ 목 ~ 사타구니 몸통이 프레임 좌우 중앙
    │
    ├── 옆 보고 서있음
    │   └→ 목 ~ 사타구니 몸통이 프레임 좌우 중앙
    │      (팔·다리 위치 무시)
    │
    └── 옆 보고 앉아있음
        └→ 팔·어깨 ~ 무릎 범위가 프레임 좌우 중앙
```

**빠른 참조 표**

| 샷 타입 | 좌우 위치 | 처리 |
|---|---|---|
| **풀샷** | 중앙 (≤ 4:6) | **A** 모델 정중앙 + 상단 여백 ≥ 40, 하단 여백 ≥ 20 |
| **풀샷** | 치우침 (> 4:6) | **B** 사이즈 ↑ → 좌우 중앙 / 크롭은 다리쪽만 |
| **웨이스트~니샷** | 무관 | **C** 모델 정중앙 + 머리 상단 여백 ≥ 40 |
| **바스트샷** (상하 여백 X) | 무관 | **D** 사이즈 ↑ → 머리 보호 + 좌우 중앙 |

> **공통**: "좌우 중앙"의 기준선은 자세에 따라 다름 — 정면 서있음/앉아있음·옆 서있음 = **목~사타구니 몸통**, 옆 앉아있음 = **팔·어깨~무릎 범위**.

### 마커 기반 토르소 정렬 워크플로우

> 자동화로 화보 배치 후 토르소가 살짝 어긋났다고 판단할 때 사용한다. "약간 왼쪽" 같은 모호한 자연어 대신 **시각적 좌표**로 의사소통한다.

**5단계 프로세스:**

1. **마커 추가** (사용자): 프레임 안에 `#000000` RECTANGLE을 그려 **현재 보이는 토르소(또는 핵심 신체)의 위치**를 표시. 마커 크기는 가시 토르소 영역을 대략 덮을 정도면 충분.
2. **마커 좌표 추출** (자동화): 프레임의 자식 RECT 중 fill이 `#000000`인 것을 찾아 `(x + w/2, y + h/2)` = 현재 토르소 중심 좌표를 얻는다.
3. **원본 좌표 역산**: 현재 화보 rect의 `(rect_x, rect_y, scale)`로 마커 중심의 **원본 이미지 좌표** `(torso_orig_x, torso_orig_y)`를 역산한다.
   - `torso_orig_x = (marker_cx − rect_x) / scale`
   - `torso_orig_y = (marker_cy − rect_y) / scale`
4. **새 위치·스케일 계산** — 토르소를 프레임 중앙으로 이동시키는 `(rect_x_new, rect_y_new, scale_new)`:
   - `rect_x_new = frame_center_x − torso_orig_x × scale_new`
   - **커버 조건**: `rect_x_new ≤ 0` AND `rect_x_new + image_w × scale_new ≥ frame_w`
   - 두 조건 정리 → **최소 스케일**: `scale_new ≥ (frame_w − frame_center_x) / (image_w − torso_orig_x)`
   - 즉 **원본 토르소가 이미지 중앙에서 한쪽으로 치우칠수록 더 큰 스케일이 필요** → 모델의 다른 부분이 더 클립된다.
5. **마커 삭제**: 정렬 완료 후 마커 rect를 `remove()`로 제거.

> ⚠️ 사용자가 추가한 마커는 **현재 토르소 위치**를 표시한다 (목표 위치 아님). "marker 중심 → frame 중앙"으로 이동하는 방향으로 시프트한다.

### 풀샷 (Rule A) 상단:하단 = 2:1 정확 계산

`top = 40, bottom = 20` 정확히 맞추기 위한 공식 (340×440 기준):

- **가용 마진 합** = `frame_h − model_h_frame` (예: 440 − 380 = 60)
- 2:1 분배 → `top = 40, bottom = 20`
- **모델 가시 영역(원본 픽셀)** = `feet_orig − head_orig` (이미지 안에서 머리끝~발끝 픽셀 수)
- **scale** = `(frame_h − top − bottom) / (feet_orig − head_orig)`
- **rect_y** = `top − head_orig × scale` (보통 음수 — 위쪽 오버플로 양)

> ⚠️ **trade-off**: `top ≥ 40` + `bottom = top/2` + 토르소 수평 정중앙은 이미지 종횡비·모델 비율에 따라 **동시 만족 불가**할 수 있다. 우선순위: **마진 규칙 ≥ 수평 정중앙** (수평 약간 어긋남 허용). 그것도 어려우면 Figma AI 배경 확장으로 좌우 여백을 만든다 (위 「화보 이미지 배치」 참고).

## 로고·누끼 이미지 처리 (배경 제거 · 여백 없이 · 원본 비율 유지)

> 로고와 상품 누끼 이미지에 **공통으로 적용**되는 원칙입니다. 화보(크롭 금지)와는 별개의 **자산 처리 규칙**입니다.

- **로고와 누끼(상품) 이미지는 모두 「배경 제거 + 여백 없이 + 원본 비율」 상태로 사용한다.**
  - 화보와 마찬가지로 **크롭 금지** — 원본 비율 그대로 유지.
  - 이미지 주변 **여백(흰색·회색 공간)을 제거**해 콘텐츠가 프레임 가장자리까지 닿게 배치한다.
- ⚠️ **업로드 단계 RECT 비율 = 이미지 원본 비율**. `scaleMode: FILL`은 RECT 비율과 이미지 비율이 다르면 자동 크롭하므로, **임시 RECT라도 반드시 원본 비율로 사전 resize**해 둔다.
  - ❌ Anti-pattern: 100×100 정방형 RECT에 1440×1890 누끼 fill → 위·아래 잘려서 배치됨 (원본 비율 손실, 이후 가공 의미 없음).
  - ✅ Correct pattern: 누끼 1440×1890이면 RECT 비율 1440/1890=0.762로 (예: 100×131.25, 80×105 등). `upload_assets`는 PNG/JPG dim을 자동 보정하지 않으므로 호출 전에 원본 dim을 `sips -g pixelWidth -g pixelHeight` 등으로 확인하고 RECT 사이즈를 미리 결정한다.
  - 일괄 업로드 시 같은 비율 자산끼리 행으로 묶어 RECT 사이즈를 통일하면 그리드 정렬도 깔끔해진다.
- **배경이 있는 경우**: Figma 에디터에서 **Figma AI(Remove background)**로 제거한다. 자동화 API(`use_figma`)로 호출 불가하므로, **업로드 위치(노드 ID·페이지명)를 사용자에게 알리고 직접 적용을 요청**한다.
- **이미 배경이 없는 경우(SVG · 투명 PNG 등)**: **사용자에게 배경 제거를 요청할 필요 없이** 그대로 사용한다.
  - 업로드 직후 이미지에 **alpha 채널이 있는지(투명 배경인지) 먼저 확인**한다 — 투명이면 그대로 진행, 불투명이면 요청.
- ⚠️ **누끼 처리 = 블록(blocking) 워크플로우**: 누끼는 **별도 위치에 먼저 업로드**한 뒤 사용자 가공 → **「가공 완료」 신호 받은 뒤** 03 swp/scl product 셀을 빌드한다. **가공 전 원본 누끼를 셀에 박지 않는다**(셀 안 이미지 hash가 자동 교체되지 않거나 셀별 개별 처리가 필요해지는 anti-pattern). 상세 절차: [[1-2. 시안]] Step 6.
- ⚠️ **alpha bbox 크롭은 배경 제거의 필수 후속 단계**: Figma AI Remove background는 **배경 픽셀을 alpha=0으로 만들 뿐 캔버스 크기는 유지**한다 → 결과 PNG의 alpha bbox 바깥에 **투명 여백이 남는다**. 이 상태로 cell에 fill 하면 셀마다 상품 면적이 달라져 그리드 통일감이 깨진다. **반드시 PIL `getbbox()` + `crop()`으로 alpha bbox만 남기고 잘라낸 뒤 재업로드**해 fill 교체한다.
  - **워크플로우 5단계**: ① `figma.getImageByHash(hash).getBytesAsync()` 로 가공된 PNG bytes 추출 → ② `from PIL import Image; img = Image.open(...); bbox = img.getbbox()` 로 alpha bbox 계산 → ③ `cropped = img.crop(bbox)` 로 여백 제거 → ④ `upload_assets`로 cropped PNG 재업로드(새 hash 발급) → ⑤ 모든 product 셀의 RECT fill을 새 hash로 교체.
  - **RECT 사이즈 = 동일 면적, 가변 비율**: 크롭 후 aspect ratio가 상품별로 다르므로 RECT를 일률 사이즈로 두면 다시 잘리거나 여백이 생긴다. **목표 면적 S(예: 6,431 px²)를 고정**하고 각 RECT를 `w = √(S·a), h = √(S/a)` (a = bbox_w / bbox_h)로 산정하면 **시각 면적은 균등 + 비율은 원본 유지**. 셀 내 중앙 정렬은 그대로.
  - **anti-pattern**: 크롭하지 않고 일률 RECT(예: 70×91.875) + `scaleMode: FILL`로 박는 것 — alpha 여백이 그대로 표시되어 상품마다 시각 면적이 다르게 보임. 크롭 누락은 모든 swp/scl 페이지 본문 빌드의 사전 조건 위반이다.
- ⚠️ **로고도 alpha bbox 크롭 필수**: 클라이언트가 보낸 로고 PNG에 **상하 또는 좌우에 alpha=0 여백이 박혀 있는 경우가 많다** (디자이너가 로고를 일정 캔버스에 맞춰 저장하면서 발생). 누끼와 동일한 alpha bbox 검증·크롭 절차를 거친다.
  - **검증 방법**: 임시 RECT(source 원본 사이즈)에 magenta `#FF00FF` 등 강조색 backing rect를 깐 뒤 `node.screenshot({ scale: 12 })`로 캡처 → 로고 콘텐츠 주위 magenta 노출 영역이 alpha 여백. 정상 로고는 magenta가 거의 안 보여야 한다.
  - **두 가지 fix 옵션** (상황에 따라 선택):
    - **A. 소스 PNG 크롭 후 재업로드** (정공법, 누끼와 동일): ① `getBytesAsync()` → ② PIL `getbbox()` + `crop()` → ③ `figma.createImage()` 로 새 hash → ④ 모든 로고 RECT의 fill을 새 hash로 교체 + 새 비율에 맞춰 RECT resize.
    - **B. `scaleMode: "CROP"` + `imageTransform`으로 가시 영역만 샘플링** (소스 PNG 그대로): `imageTransform = [[x_scale, 0, x_offset], [0, y_scale, y_offset]]` (가시 bbox 정규화 좌표 0~1). 예: 가시 영역 y=[0.22, 0.82], x=[0.06, 0.96]이면 `[[0.90, 0, 0.06], [0, 0.60, 0.22]]`. **rect 비율도 가시 콘텐츠 비율에 맞춰 리사이즈**해야 stretch/letterbox 없이 fit (`rect_w = √(S·a), rect_h = √(S/a)`, a = 가시 콘텐츠 aspect, S = 페이지 유형별 기준 면적 px²).
  - **언제 어느 옵션?** 같은 hash를 여러 페이지가 공유하는 경우(예: `04-BG` + `04-swp1` 모두 동일 maje hash 사용) **B가 효율적** (소스 1번 그대로, fill만 일괄 update). 소스 PNG를 정리하고 싶거나 향후 다른 자산 파이프라인과 통합한다면 A.
  - **anti-pattern**: 로고 RECT 비율을 단순히 페이지 면적 비율(0.5%·2.3% 등)만 맞추고 alpha 여백 검증 누락 → 가시 영역 비율이 다르므로 시각 비중이 어긋남(스펙에는 부합하지만 작아 보이거나 한쪽으로 쏠려 보임).
- 적용 범위: **시안·초안 모든 페이지 공통.** 로고(01·02·표지·OG)와 누끼(03 swp·scl)에 동일하게 적용.

### ⚠️ 로고 프레임 정규화 (clone + rescale 패턴) — 면적 검증의 사전 조건

> alpha bbox 크롭과 별개로, **Figma 안에서 로고 프레임 자체가 실제 로고 bbox와 일치해야** 면적 검증(2.5%·1.2%·0.5% 등)이 의미를 갖는다. 프레임 안에 빈 여백이 있으면 `node.width × node.height` 산출 면적이 실제 시각 면적보다 커져 규칙 통과 여부가 거짓이 된다.

**핵심 원칙**
- 로고 프레임의 width·height = **가시 벡터/이미지 bbox와 동일**해야 한다 (tight bbox).
- 프레임 안에 좌우·상하 빈 여백이 있으면 → **clipsContent를 풀어 해결하지 말 것** (clip이 풀리면 인접 콘텐츠를 침범).
- 내부 벡터를 하나하나 `resize()`로 만지면 Figma가 벡터 bounds를 재계산하면서 **미세한 어긋남**이 발생.
- 부모 프레임만 리사이즈하고 내부 벡터를 따로 조정하는 패턴 = **anti-pattern** (프레임 면적과 실제 로고 bbox가 분리됨 → 규칙 검증 무효).

**정공법: 정상 source clone + rescale() 균등 스케일** *(가장 안전·정확)*

```
1. 여백 없이 tight bbox 상태인 정상 로고 프레임을 source로 식별
   예: 시안 표지 A의 `logo-bk` (검정 워드마크 source)
       02 페이지의 `_레이어_1` (흰색 02 로고 source)

2. source frame을 clone (Figma `node.clone()` — 부모 프레임 + 내부 벡터 전체 복제)

3. rescale(scale)로 부모 프레임과 내부 벡터를 한 번에 균등 스케일
   - scale = √(목표 면적 / 현재 면적)
   - 예: 현재 5,564 px² (214×26) → 목표 5,500 px² (01-A·B 분리형)
     → scale = √(5500/5564) = 0.9942

4. 기존 문제 로고를 clone으로 교체
   - 위치만 옮기고(부모 프레임 안에서 x·y 조정) 면적은 손대지 않는다

5. clipsContent는 끄지 않고 유지

6. 면적 검증은 로고 프레임 `width × height`로 계산
   (alpha bbox + tight frame이 보장된 상태이므로 이 값이 곧 시각 면적)
```

**유형별 정상 source 노드 (쁘렝땅 시안 기준 — 다른 브랜드에서도 같은 패턴 적용 가능)**

| 사용처 | source 노드 ID | 타입 |
|---|---:|---|
| 검정 워드마크 (시안 표지·01) | 시안 표지 A의 `logo-bk` | tight bbox + clipsContent |
| 흰색 02 로고 | A02의 `_레이어_1` | tight bbox + clipsContent |

**최종 검증 (3 케이스 동시 적용)**
1. 프레임 면적 (`w × h`) = 페이지 유형별 기준 비율 ±10% (예: 01 분리형 ~2.5%, 02 ~1.2%, OG ~9.5%)
2. 프레임 내부 alpha bbox = 프레임 사이즈와 거의 일치 (magenta backing rect로 확인)
3. clipsContent = true 유지 (False 발견 시 즉시 True로 되돌리고 내부 벡터 사이즈 재확인)

> ⚠️ **삭제된 노드 ID 참조 금지**: 정규화로 교체된 후 기존 문제 로고 노드는 더 이상 최종 로고가 아니다. 후속 작업에서는 **새 clone 노드 ID**를 사용한다 (예: 쁘렝땅 OG `16754:330`, A01 `16754:339`, B02 `16754:348`).

### 1. 로고 타입 (기본값)
단색 배경 위에 브랜드 로고를 배치

- **정렬**: 수직·수평 중앙 정렬
- **로고 크기 (면적 기준)**:
  - OG 프레임 전체 면적 = 800 × 400 = **320,000 px²**
  - 로고는 **「배경·여백이 제거된 bounding box」 면적이 OG 프레임 면적의 약 9~10%** (≈ 28,800~32,000 px²)가 되도록 한다.
  - **면적 기준이므로 로고 가로세로 비율(가로로 긴 워드마크 · 정사각 · 세로로 긴 심볼 등)에 관계없이 시각 비중이 일정**하게 유지된다 — 너비%로 환산하면 가로로 긴 로고는 작아 보이고 세로로 긴 로고는 커 보여 비중이 어긋나기 때문.
  - **참조**: `maje` (워드마크) — 268 × 113 = 30,284 px² → **9.46%** · 노드 `16292:330`
