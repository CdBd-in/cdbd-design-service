## 개요

CdBd 멀티페이지는 **페이지 컨테이너** 안에 **여러 페이지**가 있고, 각 페이지는 **여러 카드**로 구성됩니다. 룩북 결과물은 카드 단위로 내보낸 뒤, CdBd 에디터에서 적절한 카드에 등록합니다.

- **피그마(디자인) ↔ CdBd(렌더)**: 디자인은 카드의 시각 결과만 책임지고, **링크·구분선·gif 등 상호작용 요소는 CdBd 측이 부여**합니다.
- **내보내기 단위 = 카드 단위**: 한 페이지가 여러 카드로 구성되면 파일도 카드 수만큼 분할해 내보냅니다 (예: scl의 `03-1`, `03-2-1`, `03-2-2`…).

#### 🔧 레이어 (`block.layers[]`) JSON schema (실측 검증 — 2026-06-09)

이미지 카드·갤러리 카드 모두 `block.layers` array (block 직속, gallery 안 아님)로 오버레이 보관. 각 layer item:

```json
{
  "id": "nanoid_21chars",         // 예: "4J7quNCxhKJ4F2z5fp7Or"
  "url": "https://...signed_url...",
  "size": 19,                      // 단일 숫자, 카드 width 대비 % (1~100)
  "filename": "B03-text-layer",    // 확장자 없는 파일명 (UI 표시용)
  "position": {                    // % 단위 (카드 좌상단 기준)
    "x": 5,                        //   x: 카드 width 대비
    "y": 3                         //   y: 카드 height 대비
  },
  "linkButton": null               // 또는 page/url/call 형식 (위 「링크 연결」 schema)
}
```

**핵심 포인트**:
- `block.layers`는 **block 직속 속성** — gallery 카드도 `block.gallery.layers`가 아니라 `block.layers`에 보관 (gallery 카드 schema는 별도 `block.gallery.images`와 분리)
- `size` = **width %만** 지정 (height는 원본 비율로 자동 계산)
- `position.x`, `position.y` = **카드 좌상단 기준 % 좌표**
- `linkButton: null`이면 클릭 무반응. 외부 URL·전화·페이지 이동 모두 위 「[「링크 연결」 = `linkButton` 키](#%E2%9A%A0%EF%B8%8F-%EB%A7%81%ED%81%AC-%EC%97%B0%EA%B2%B0--linkbutton-%ED%82%A4-not-link)」 schema 그대로 적용
- **Figma 좌표 → CdBd % 변환 공식**:
  - `position.x = Figma.x / page_width × 100` (예: x=20, page=380 → 5.26)
  - `position.y = Figma.y / page_height × 100` (예: y=20, page=580 → 3.45)
  - `size = Figma.width / page_width × 100` (예: w=73, page=380 → 19.21)
- ⚠️ **basic-link 「+」 gif도 동일 schema**. 마커 위 「+」 = layer 1개, `linkButton: {type:"url", link:{href:"상품URL", openNewTab:true}}`
- 또한 갤러리 카드의 `gallery.imageOption.originalPixel`: `{"width": 1140, "height": 1740}` — 원본 픽셀 정보 (optional, UI에서 자동 채움)

### 갤러리 카드

> 여러 이미지를 한 카드에 담아 **3가지 유형**(나열하기 · 넘겨보기 · 그리드)으로 표시. 03 swp·scl의 모든 갤러리 시나리오를 처리.

#### 🔧 갤러리 카드 JSON schema (실측 검증 — editor 4637)

```json
{
  "id": "uuid",
  "type": "gallery",
  "style": { /* 카드 스타일 (image 카드와 동일 형식) */ },
  "title": "갤러리",
  "active": false,
  "content": "",
  "gallery": {
    "type": "swipe",      // "swipe" (넘겨보기) / "list" (나열하기) / "grid" (그리드)
    "images": [
      { "id": "uuid", "url": "https://...signed_url..." },
      { "id": "uuid", "url": "https://..." }
    ],
    "imageOption": {
      "style": { "aspectRatio": "auto", "borderRadius": "0px" }
    },
    "gridTypeOption":  { "column": 3, "rowGap": 16, "columnGap": 16 },
    "listTypeOption":  { "rowGap": 16 },
    "swipeTypeOption": {
      "autoPlay": false,
      "navigation": false,       // ⚠️ 인디케이터 — 사용자 명시 요청 없으면 항상 false (꺼둠)
      "infiniteLoop": false,     // 무한 반복
      "verticalSwipe": false     // 세로 스와이프
    }
  },
  "disabled": false,
  "previewText": null
}
```

**핵심 포인트**:
- `gallery.images[i]`는 `{id, url}` 2 필드만 필수 (이미지 카드의 `content` URL이 여기선 `url`로 들어감)
- 유형 변경(swipe/list/grid)에 따라 `gridTypeOption`·`listTypeOption`·`swipeTypeOption` 중 해당 항목만 활성, 나머지는 기본값으로 유지 (UI가 셋 다 항상 저장)
- 카드 `style.padding`이 갤러리 카드 내부 여백 (UI 「카드 디자인 → 내부여백」)
- 카드 `style.margin`이 카드 외부 여백 (UI 「카드 디자인 → 외부여백」). 3-value shorthand "상 좌우 하" 사용

> ⚠️ **`swipeTypeOption.navigation` (인디케이터) 기본값 = false**
> 갤러리 카드의 swipe 인디케이터(○○●○ 점 표시)는 사용자가 **명시적으로 요청한 경우에만 true**로 설정한다. 명시 요청 없으면 항상 **false** (꺼둠). 룩북 화보 스와이핑은 인디케이터 없는 깔끔한 노출을 기본으로 한다 (PPT 의뢰서가 인디케이터를 디자인 모형에 그리지 않은 경우 = 대부분 케이스).

## 페이지 유형별 카드 매핑

각 룩북 페이지 유형이 **어떤 CdBd 카드**에 **어떤 옵션 값**으로 들어가는지. 파일명은 [[1-1. 공통]] 참고.

> **속성 표기 규칙**: `옵션명=값` 형식. 카드 디자인 옵션 중 룩북 기본값(외부여백=0 등)은 생략. (확인 필요)는 실측 미완 항목.

### OG 이미지 (멀티페이지 1장)

| 파일 | 등록 위치 | 속성 |
|---|---|---|
| `og.jpg` | **상단 「URL 생성하기」 → URL 정보 편집하기 → 공유 데이터 → 썸네일** | 권장 800×400px · 1배수 JPG ([[1-1. 공통]] 참고) · 멀티페이지 전체 1장 |
| (제목) | 같은 모달 → 제목 | **브랜드명(영문)** (예: `PRENDANG`) |

### 03 — look-gallery (화보 스와이핑 갤러리)

**1 멀티페이지 페이지에 1 갤러리 카드(넘겨보기)**, 카드 안에 같은 LOOK의 화보 컷 N장. 페이지마다 카드 분리 ❌ (1 LOOK = 1 카드).

| 파일 | CdBd 카드 / 설정 | 속성 |
|---|---|---|
| `A03-1.jpg`, `A03-2.jpg`, … (또는 `03-1.jpg`, `03-2.jpg`, …) | 갤러리 (넘겨보기) | 유형=넘겨보기 · 비율=원본 · 내비게이션=OFF (요청 시에만 ON) · 무한 반복=OFF · 자동 넘김=OFF · **카드 디자인 → 외부여백=0(풀블리드) · 내부여백=0** · 모서리=각진 · 링크 연결=없음 (다음 페이지로의 이동은 페이지 단위 스와이프) |

- **컷 수**: PPT 의뢰서의 LOOK 슬라이드별 화보 컷 수를 그대로 (공통 자산 제외 후 카운트 — [[1-2. 시안]] Step 5 PPT 매핑 절차 참고).

## CdBd 등록 워크플로우

**트리거**: 사용자가 **"(시안/초안) 이미지 CdBd 콘텐츠로 만들어줘"** · **"CdBd 페이지 만들어줘"** · **"CdBd에 등록해줘/올려줘"** 같은 요청을 할 때. **시안·초안 같은 워크플로우** (폴더 경로·파일 패턴·슬러그 규칙만 분기).

**전제**:
- 내보내기가 완료되어 다음 폴더에 파일이 있어야 함 ([[1-1. 공통]] 「저장 위치」):
  ```
  ~/Desktop/CdBd/제작서비스 {YYYY}/{MM}/{브랜드명(국문)}/작업파일/시안/   (시안)
  ~/Desktop/CdBd/제작서비스 {YYYY}/{MM}/{브랜드명(국문)}/작업파일/초안/   (초안)
  ```
  - `YYYY` = 연도(예: `2026`), `MM` = 작업 시작/저장 시점의 시스템 월 2자리 zero-pad(예: `06`).
  - 해당 월 폴더에 파일이 없으면 직전 월 폴더(시즌 시작 월)도 확인하고, 없으면 사용자에게 정확한 경로를 묻는다.
- CdBd 계정 (현재: `account@emka.group`)
- 브랜드 영문명·컬렉션명·(초안 슬러그) 정보 — 우선 `[문서]` 폴더(엑셀·PPT)에서 확인, 없으면 사용자에게 묻기

### 제작 단계 (Step by Step)

#### 1. 시안/초안 구분 + 폴더 파일 점검
- 사용자가 명시하지 않으면 「시안」/「초안」 중 무엇을 등록할지 확인
- 해당 폴더의 파일 목록을 글로브로 확인하고 **누락 여부 점검**:
  - **시안**: `og.jpg`, `A.jpg`, `A01.jpg`, `A02.jpg`, `A03*.jpg`, `B.jpg`, `B01.jpg`, `B02.jpg`, `B03*.jpg` (03은 swp/scl이면 `A03-BG.jpg`·`A03-swp1.jpg` 등 세부 파일)
  - **초안**: `og.jpg`, `01.jpg`, `02.jpg`, `03*.jpg`, …
- 누락이 있으면 사용자에게 알리고 진행 여부 확인

#### 2. 브랜드 영문명·컬렉션명 확인
- **브랜드 영문명** (URL 슬러그·OG 제목용) — `[문서]` 폴더에서 확인, 없으면 사용자에게 묻기 (예: `PRENDANG`)
- **컬렉션명** (OG 설명용) — `[문서]` 폴더에서 확인, 없으면 사용자에게 묻기 (예: `26 SS Collection`)

#### 3. GStack 브라우저 + CdBd 로그인
- `open-gstack-browser` 스킬로 표시 브라우저 실행 (사용자가 함께 확인)
- `https://cdbd.in` 접속 → 로그인 (`account@emka.group`). 이미 로그인되어 있으면 스킵

#### 4. 새 멀티페이지 생성
- 홈 → 「+ 새 페이지 만들기」 → **「멀티페이지 BETA」** → 추천 **380×580px** → 「시작하기」
- 페이지 테마 설정 위저드: 폰트 **프리텐다드** 유지 → 「다음」 → 색상 기본 → 「완료」

#### 5. 페이지별 카드 등록 (파일 순서대로)
- **시안 등록 순서 (8페이지)**: `A 표지` → `A01` → `A02` → `A03` → `B 표지` → `B01` → `B02` → `B03`
- **초안 등록 순서**: `01` → `02` → `03` → … (순차)

각 페이지마다 위 「페이지 유형별 카드 매핑」 표를 따라 카드 등록:

| 페이지 유형 | 등록 절차 |
|---|---|
| **시안 표지** (`A`/`B`) | 새 페이지 → 이미지 카드 → 파일 업로드 → 비율=원본·크기=100·**카드 여백 없음(내부=0·외부=0)**·**링크 연결=페이지 이동하기 → 다음 페이지**(A 표지→A01 / B 표지→B01) |
| **01 페이지** | 새 페이지 → 이미지 카드 → 파일 업로드 → 비율=원본·크기=100·**카드 여백 없음**·**링크 연결=페이지 이동하기 → 다음 페이지**(A01→A02 / B01→B02 / 01→02) |
| **02 페이지** | 새 페이지 → 이미지 카드 → 파일 업로드 → 비율=원본·크기=100·**카드 여백 없음**·링크 연결=없음 (사용자가 스와이프로 03으로 이동) |
| basic (full·frame·footer) | **01·02와 동일** → 새 페이지 → 이미지 카드 → 파일 업로드 → 비율=원본·크기=100·**카드 여백 없음**·링크 연결=없음 |
| **basic-link** (예외) | basic과 동일한 이미지 카드 등록 + **예외 단계**: **레이어 추가**로 「+」 gif를 각 마커 위치에 얹고 각 레이어에 **링크 연결 → URL 열기**(상품 URL · 새 창에서 열기=ON) — 상품별 URL을 `[문서]`에서 확인, 없으면 사용자에게 묻기. **gif 사이즈·마커 선과의 간격은 위 「basic-link 「+」 gif 레이어 위치·사이즈」 참고 콘텐츠**(michaa 시즌별 룩북) **한 페이지 이상을 열어 시각 매칭** |
| **look-gallery** (화보 스와이핑 갤러리) | 새 페이지 → 갤러리 카드(유형=넘겨보기, 내비게이션=OFF (요청 시에만 ON), 무한 반복=OFF, 자동 넘김=OFF) → 카드 디자인 **외부여백=0·내부여백=0(풀블리드)** → 같은 LOOK의 화보 컷 N장을 **카드 1개에 모두 업로드**(`A03-1`, `A03-2`, … 순서) → 페이지마다 카드 분리 ❌ |
| swp (상품 누끼 그리드) | 새 페이지 → 사이드바 케밥 → **페이지 배경 설정 → 이미지(`03-BG`)** (있으면) → 갤러리 카드(유형=넘겨보기, 내비게이션=OFF (요청 시에만 ON)) → `03-swp1`·`03-swp2`·… 순서로 업로드 |
| scl | 새 페이지 → BG 있으면 **페이지 배경 설정 → 이미지(`03-BG`)** → 이미지 카드(`03-logo`, 비고정) → 갤러리(넘겨보기, `03-1`) → 갤러리(그리드 또는 나열하기, `03-2`) → scl-row면 행 사이에 구분선 카드(`#292929` 두께 1 투명도 20% 실선) |
| 매장 정보 | **요소별 카드 조합으로 등록** (페이지 1장 이미지 X). 텍스트(타이틀) → 이미지 카드(list 행, 1행=1장 / grid는 2단 카드) → 구분선 카드(행 사이) → 버튼 카드(텍스트만, chevron 없음) → 이미지 카드(헤더 또는 푸터 로고). **각 list 행에 `tel:{전화번호}` 링크 레이어 추가**. 푸터 로고는 basic류=**하단 고정** / scl류=**고정 X**. **`store-basic-cover`만 예외**: basic-link 방식(합본 이미지 + 외부 링크별 레이어). 페이지 유형별 카드 시퀀스는 위 「페이지 유형별 카드 매핑 → 매장 정보」 참고 |

#### 6. URL 정보 편집 (상단 「URL 생성하기」)
- **페이지 주소 슬러그**:
  - **시안**: `{브랜드영문명 소문자}_{YYMM}` 자동 (예: `prendang_2606` — 작업 시점 년월). 사용자에게 묻지 않음. ⚠️ **CdBd 슬러그는 언더바(`_`)만 허용** — 대시(`-`) 사용 불가
  - **초안**: `[문서]`에서 슬러그 요청 확인 → 없으면 **사용자에게 묻기**
- **공유 데이터**:
  - 썸네일 = `og.jpg` 업로드 (800×400)
  - 제목 = 브랜드 영문명 (예: `PRENDANG`)
  - 설명 = 컬렉션명 (예: `26 SS Collection`)
- 페이지 비밀번호: OFF (요청 없으면) · **페이지 상단 메뉴: OFF (기본 — 요청 시에만 ON)** — `editor_published.is_menu = false` 명시 PATCH

#### 6.5. 최종 검증 체크리스트 (게시 전 필수)

게시 직전 자동 검증해 누락·치수 어긋남 잡기. **각 항목을 코드/자동화로 확인**한 뒤 사용자에게 보고.

- [ ] **페이지 수 일치** — Figma 원본 디자인 페이지 수 = CdBd 페이지 수
- [ ] **페이지 순서 일치** — Figma 디자인 페이지 순서 = CdBd 페이지 순서 (시안 표지 → 01 → 02 → 03 등 / 매장 정보 mg-1 → mg-2 → mg-3)
- [ ] **페이지별 카드 시퀀스** — 위 「페이지 유형별 카드 매핑」 표의 카드 종류·순서·옵션 그대로 적용됨
- [ ] **⚠️ 페이지별 로고·헤더 면적 = Figma 측정값 정확 일치** (아래 「로고 면적 검증 공식」 참고)
- [ ] **누락된 로고/헤더 없음** — Figma 페이지에 로고가 있는데 CdBd엔 빠지지 않았는지
- [ ] **불필요한 로고 없음** — Figma엔 없는데 CdBd에 잘못 추가되지 않았는지
- [ ] **구분선·여백** — 그리드 일치(`margin LR 32`), 다크 BG면 `#fafafa`·라이트 BG면 `#292929`·두께 1·투명도 20%
- [ ] **버튼 height** — Figma 버튼 높이 = `세로 padding × 2 + text line-height` 공식 일치 (위 「버튼 height 조정」)
- [ ] **링크 연결** — 전화/URL 모두 `linkButton` 표준 schema (위 「「링크 연결」 = `linkButton` 키」)
- [ ] **텍스트 시각 결과 일치** — Figma textCase=UPPER → CdBd text도 대문자 (위 「Figma 시각 결과 → 카드 데이터 변환」)
- [ ] **URL 정보** — 슬러그·OG·제목·설명 매핑 표 기준
- [ ] **에디터 close 상태** — race condition 회피

##### ⚠️ 로고 면적 검증 공식

| 측정 | 환산 |
|---|---|
| Figma 로고 frame width (px) | CdBd `style.width` = `(Figma_width / 380) × 100` % |
| 예: Figma 68px | CdBd **18%** (= 68 / 380 × 100 = 17.89%) |
| 예: Figma 51px | CdBd **13%** (≈ 51 / 380 × 100 = 13.42%) |
| 예: Figma 헤더 380px (full-width) | CdBd **100%** |
| height | 자동 (이미지 비율 유지, % 별도 설정 불필요) |

**검증 절차 (자동화)**:
1. Figma `get_metadata`로 페이지별 로고 frame `width × height` 측정
2. CdBd editor GET → 페이지별 image 카드 `style.width` 추출
3. 환산값 비교 — Figma_width / 3.8 % 와 CdBd width % 가 ±0.5% 이내인지
4. 어긋나면 PATCH로 정정 후 보고

**자주 발생하는 어긋남**:
- "20%로 박았는데 Figma는 68px (18%)" — 슬라이더 기본값 의존 안티패턴, 정확한 환산값 사용
- "Figma 헤더 380×52 → CdBd 100% (= 380px)" ✓ 헤더는 width 100%이 표준 (높이는 비율로 자동)

#### 7. 게시 전 사용자 확인 → 게시 → URL 보고
- **게시 직전 사용자에게 한 번 확인** — 모달 입력값(슬러그·제목·설명·OG)이 의도와 맞는지

| 페이지 배경 | divider `borderTopColor` | opacity |
|---|---|---|
| 라이트 (`#FFFFFF`/`#EBEBEB` 등) | `#292929` | 0.2 |
| 다크 (`#141414`/`#000000` 등) | `#fafafa` | 0.2 |

`theme.base.background` 값을 보고 자동 선택하는 게 안전 (HEX → luminance 계산 또는 단순 다크/라이트 판별).

⚠️ **anti-pattern**: 모든 페이지에 `#292929` 일률 적용 → 다크 BG 페이지에서 divider 안 보임 → 사용자 보고 "구분선 누락"으로 인식.

## Supabase 직접 자동화 (개발자/AI용)

> **목적**: CdBd UI 우회한 직접 API 자동화 경로. 위 「CdBd 등록 워크플로우」(디자이너 수동 절차)와 동일 결과를 빠르게 처리. UI 자동화(React PointerEvent·dropzone 등)는 비효율 → Supabase 직접 호출이 깔끔.

### ⚠️⚠️ (최상위 원칙) 디자인 보드 메뉴 1:1 매핑 키만 사용

**모든 자동화 PATCH는 CdBd 에디터 「디자인 보드 → 디자인」 메뉴에 실제로 존재하는 옵션과 1:1 대응되는 키만 변경한다.** 자동화가 끝난 후 사용자가 UI를 열어 동일 값을 보고 수정할 수 있어야 한다.

**왜 중요한가**: 자동화가 임의 키나 shotgun 패턴을 박으면, 사용자가 UI 메뉴로 값을 바꿔도 변경되지 않는 키가 남아 디자인이 의도와 어긋난다. UI 메뉴는 자동화 결과를 「소스 오브 트루스」로 간주하므로, **자동화 출력 ⊆ UI 입력 가능 범위** 가 항상 성립해야 한다.

⛔ **금지 패턴**

| 안티 패턴 | 문제 | 대신 |
|---|---|---|
| `fixed`/`pinned`/`sticky`/`isFixed`/`position`/`fixedPosition` 동시 true 설정 (shotgun) | UI 토글이 정확히 어떤 한 개 키를 set/unset하는지 모름 → UI off 했을 때 나머지 키가 남아 동작 차이 발생 | UI에서 직접 한 번 토글 후 GET diff로 **정확히 한 개 키** 식별 → 그 키만 사용 |
| `link.href`만 직접 박기 | UI 「링크 연결」 메뉴는 `linkButton` 키를 읽고 씀 → 데이터는 들어가지만 UI 메뉴는 비어 보임 + 클릭 무반응 | `linkButton` 키 (검증된 schema 사용) |
| `style.margin`/`padding` 변경 시 정확한 값이 UI 메뉴 입력칸에 들어갈 수 있는지 확인 안 함 (예: 4-value, 비정상 단위) | UI 메뉴가 파싱 못해 빈칸으로 표시 | 3-value `"상 좌우 하"` shorthand (UI 메뉴 입력 형식과 동일) |
| 매핑 표에 없는 키 추측 추가 (예: `alignSelf`, `justifySelf`, `horizontalAlign` 등 정렬 후보) | UI 메뉴에 존재하지 않거나 다른 키가 표준 → 데이터 무시 + 사용자 수정 불가 | 매핑 검증 후 사용. 모르면 사용자에게 「UI 어느 메뉴로 변경하면 되나요?」 물어보기 |

✅ **허용 패턴**: 아래 「카드별 디자인 보드 메뉴 → JSON 키 매핑」 표에서 **「UI 옵션 ↔ JSON 키」 1:1 대응이 검증된 키만 사용**.

✅ **검증 안 된 키가 필요한 경우 워크플로우**:
1. CdBd 에디터 UI에서 해당 메뉴 옵션을 임의 값으로 설정
2. `editor` row GET → 변경된 키·값 diff 확인
3. 매핑 표 갱신 (UI 옵션명 ↔ JSON 키 추가)
4. 자동화에서 그 키 사용

✅ **모를 때 기본 동작**: 임의 키 박지 말고 **사용자에게 묻기** — "이 옵션을 변경하려면 UI 어느 메뉴인가요? 직접 한 번 변경하셔서 어떤 키가 바뀌는지 확인해 주세요."

### ⚠️⚠️ 이미지 라이브러리 (사용자 자산 관리) — 카드/페이지 이미지 추가 시 필수 경유

**최상위 규칙**: 자동화로 카드(image, gallery)·페이지에 이미지를 넣을 때는 **반드시 「이미지 라이브러리」(=`image_modal` 테이블 + `user_image` 스토리지)에 등록한 뒤** 그 signed URL을 `block.content` / `block.gallery.images[].url` 에 사용한다.

**이유**: 사용자는 cdbd.in 에디터의 「이미지 추가하기 → 내 이미지」 모달에서 자신이 올린 자산을 **이름 변경·삭제·검색·재사용**으로 관리한다. raw로 user_image 버킷에 업로드만 하고 image_modal에 등록 안 하면 사용자 UI에서 보이지 않아 관리 불가 + 다른 카드에서 재선택도 불가.

#### 검증 완료 시퀀스 (2026-06-10 — editor 4355에서 실제 업로드·정리 200/204 확인)

```
1) Storage POST   /storage/v1/object/user_image/{uid}/{ts}_{rand12}.{ext}
   Headers       apikey + Bearer + Content-Type: image/{ext} + x-upsert: false
   Body          raw bytes
   ←             200  {Key, Id}

2) Sign URL POST  /storage/v1/object/sign/user_image/{uid}/{ts}_{rand12}.{ext}
   Body          {"expiresIn": 946080000}      # ~30년, cdbd.in UI가 발급하는 값과 동일
   ←             200  {signedURL: "/object/sign/user_image/{path}?token=..."}
   Full URL      {SUPABASE_URL}/storage/v1{signedURL}

3) Modal PATCH    /rest/v1/image_modal?id=eq.{modal_id}
   Headers       apikey + Bearer + Content-Type: application/json + Prefer: return=minimal
   Body          {"images": [<new_entry>, ...existing], "is_saving": false}
   ←             204
```

- **`{modal_id}`**: `GET /rest/v1/image_modal?user_id=eq.{uid}&select=id,images` → row 1개 (user 당 1 row 보장). 신규 사용자엔 row 미생성 케이스 미관측 — 만약 0 row면 헬퍼가 INSERT.
- **prepend (`[new_entry, ...existing]`)**: UI 정렬은 `view.sort='added_at'` 기준 클라이언트 측 — 배열 순서는 시각 영향 없지만, 누락/race 방지 위해 항상 최신 entry를 맨 앞으로 둔다.

#### `image_modal.images[]` entry 스키마 (필수 필드 — 누락 시 UI 깨짐)

```json
{
  "id": "{nanoid 8-4-4-4-12, [A-Za-z0-9_-]}",
  "url": "{전체 signed URL}",
  "name": "{확장자 제외 파일명, 예: 'A01'}",
  "path": "{uid}/{YYYYMMDDHHMMSS}_{rand12}.{ext}",
  "size": "{bytes as string}",
  "type": "{lowercase 확장자: 'jpeg', 'png', 'webp'}",   // 'jpg' 아닌 'jpeg'
  "pexels": null,
  "user_id": "{uid}",
  "folder_id": null,
  "created_at": "{ISO8601 UTC + ms + Z, 예: '2026-06-10T03:11:06.551Z'}",
  "deleted_at": null,
  "is_deleted": false,
  "resolution": "{W}*{H}",                           // '*' 구분자 (`x` 아님)
  "is_bookmarked": false
}
```

#### 카드 측 참조 패턴

- **image 카드**: `block.content = entry.url` (전체 signed URL 그대로)
- **gallery 카드**: `block.gallery.images[].push({id: short_nanoid(21자, no-dashes), url: entry.url})` — gallery의 image id는 image_modal id와 **별개 ID 공간** (다른 포맷). 같은 URL을 여러 카드/갤러리에서 참조해도 image_modal entry는 1장으로 유지.

#### 헬퍼: `~/.config/cdbd/image_library.py`

```python
import sys, os
sys.path.insert(0, os.path.expanduser('~/.config/cdbd'))
from image_library import (
    upload_to_library,      # 신규 업로드 + 등록
    upload_if_missing,      # 같은 name 이미 있으면 그 entry 재사용 (룩북 재작업 효율)
    list_library,           # name_filter로 검색
    find_in_library,        # exact name 매치 1장
    delete_from_library,    # 라이브러리 + 스토리지 동시 제거
    short_id,               # 갤러리 카드 images[].id 발급 (21자 no-dash)
)

# 단일 업로드
res = upload_to_library('/path/A01.jpg', name='A01')
card['content'] = res['url']

# 중복 회피 (룩북 작업에서 같은 파일명 재업로드 방지)

# 진단 (재실행 가능 — 라이브러리 상태 확인)

```

#### 운영 체크리스트
- [ ] **모든** 이미지 자산은 헬퍼 경유로 라이브러리 등록 (raw `storage/v1/object` POST 직접 호출 금지)
- [ ] `name` 필드는 **파일명에서 확장자 제거** (`A01.jpg` → `A01`) — 사용자가 라이브러리에서 보고 이해할 수 있는 이름
- [ ] `resolution`은 **`WxH` 아닌 `W*H`** (예: `1140*1740`) — UI 정렬·필터에 사용됨
- [ ] `type`은 **`jpg` 아닌 `jpeg`** — image_modal의 enum
- [ ] **재작업 시** `upload_if_missing()` 사용해 동일 name 중복 entry 생성 회피 (라이브러리 깔끔하게)
- [ ] 자동화 실수로 만든 임시 자산은 즉시 `delete_from_library(entry_id_or_name)`로 정리

### 핵심 워크플로우 시퀀스

#### 멀티페이지 신규 생성 (단순 PATCH 수동 작업과 동일)
UI에서 "새 페이지 만들기 → 멀티페이지 BETA → 380×580 → 시작하기 → 테마 위저드" 5클릭 = `editor` 테이블 신규 row 생성. **자동화 안 함** (UI 한 번이 가장 빠름).

#### 카드 등록 (`editor.pages` PATCH)
```http
PATCH /rest/v1/editor?id=eq.{editor_id}
Headers: apikey + Authorization Bearer + Content-Type: application/json
Body: {"pages": [...], "theme": {...}, "multipage_metadata": {...}}
```
`pages[0].blocks`를 새 array로 교체하면 페이지 내용 전체 변경. 응답 204.

#### ⚠️ 게시 후 수정 시 — `editor_published` 동기화 필요
`editor` 테이블 PATCH는 **편집본**만 업데이트. 이미 게시된 `https://cdbd.in/2account/{url_key}`에는 반영 안 됨 (`editor_published`가 별도 snapshot). 게시 페이지 동기화:
```http
PATCH /rest/v1/editor_published?editor_id=eq.{editor_id}
Body: {"pages": [...], "theme": {...}, "multipage_metadata": {...}, "type": "multi"}
```
응답 204. 즉시 게시 URL에 반영. 또는 사용자가 UI에서 다시 "URL 생성하기" 누르면 게시 시퀀스 12 호출이 자동 처리.

#### ⚠️⚠️ 에디터 열린 상태 PATCH = race condition (덮어쓰기)
**자동화 PATCH 전, 사용자에게 `https://cdbd.in/editor/{id}` 탭을 모두 닫게 한다.** 에디터가 열려 있으면 client-side state(현재 화면의 pages array)가 우리 PATCH 직후 다음 `save_editor_version` 호출에서 **우리 변경을 덮어쓴다**. 증상: PATCH HTTP 204 받았고 직후 GET에선 우리 데이터 확인되지만, 몇 초 후 다시 GET하면 원래 빈 상태로 돌아가 있음 (에디터 자동 저장이 덮음). `updated_at` 컬럼이 PATCH 시점보다 늦으면 덮어쓰기 확정. **회피 순서**: ① 사용자에게 에디터 탭 close 요청 → ② close 확인 응답 받기 → ③ editor + editor_published 둘 다 PATCH → ④ 사용자에게 새 탭에서 검증 요청. 단순 새로고침은 부족 — 완전히 close해야 client state가 비워진다.

#### URL 생성·게시 시퀀스 (실측 4 호출 — 2026-06-09 검증)

> ⚠️ **이전 12-호출 시퀀스는 outdated**. cdbd.in client chunk 5784 reverse-engineering 결과, **실제 호출은 4개**다. OG 이미지·image_modal 등 사용자 갤러리 단계는 `editor_published_metadata` UPSERT를 미리 처리하면 생략 가능 (게시 직전 별도 호출 안 함). 게시 시점에 client는 이미 fetch된 editor row의 snapshot을 그대로 `editor_published` UPSERT한다.

**자동화 publish 시퀀스** (반드시 이 순서):

1. **`POST /rest/v1/editor_published?on_conflict=editor_id&select=*`** — UPSERT
   - Headers: `Prefer: resolution=merge-duplicates,return=representation`
   - Body: editor row의 `{editor_id, blocks, pages, multipage_metadata, theme, user_id, updated_at, title, type, is_menu: false}` — **`is_menu`는 반드시 명시**(신규 row는 기본 `true`로 생성됨, 룩북 기본 정책은 OFF)
   - 응답: `[{id, ...}]` (게시 snapshot uuid)

2. **`PATCH /rest/v1/editor_published_metadata?editor_id=eq.{editor_id}`**
   - Body: `{is_active: true}`
   - **사전조건**: editor_published_metadata row가 미리 존재해야 함 — 없으면 먼저 UPSERT (`POST .../editor_published_metadata?on_conflict=editor_id&select=*` body `{editor_id, user_id, title, description, image, is_active: true}`)

3. **`POST https://www.cdbd.in/api/update-url-key`** ← **Next.js API route, RLS 우회 핵심**
   - Headers: `Content-Type: application/json` + `Authorization: Bearer {access_token}`
   - Body: `{editor_id, user_id, url_key}` (`url_key` = 슬러그 string)
   - 응답: `{"success": true, "isFirstTime": true/false}` — `isFirstTime` = 첫 게시 여부
   - **이 호출이 `editor_url` 테이블에 row를 INSERT 한다** (anon이 직접 INSERT 불가 — RLS)

4. **`POST /rest/v1/rpc/save_editor_version`**
   - Body: `{p_editor_id}`
   - 응답: 정수 (버전 번호, 예: 1018)

**최종 게시 URL**: `https://cdbd.in/2account/{url_key}` (= cdbd.in의 user_url 테이블의 `site_key` = "2account").

**검증**: `SELECT * FROM editor_url WHERE editor_id = {id}` → row 1개 (url_key, created_at). row가 있으면 게시 성공.

> ⚠️ **이전 표기 `extend_published_url_v2` RPC는 존재하지 않음** (PGRST202 not found). chunk 5784에 검색해도 없음. URL 등록은 Next.js API route `/api/update-url-key`가 service-side에서 처리 (Supabase service_role 또는 admin 권한으로 RLS 우회).

> ⚠️ **자동화 4-call publish 후 "게시 중지" 상태 해결법** (2026-06-09 실측 검증)
> 위 4-call 시퀀스를 정상 실행하고 `editor_url` row + `editor_published.is_active=true`인데도 뷰어가 **"게시 중지 혹은 삭제된 페이지입니다"** 표시되는 케이스가 있음 (PRENDANG 4739 사례 첫 publish).
> - **해결 방법 (실측 검증)**: 다음 5-call 시퀀스로 publish/republish — **`editor_published` PATCH로 동기화 + metadata.is_active=true 재set 핵심**
>
> ```
> 1. PATCH /rest/v1/editor?id=eq.{editor_id}
>    {pages, title, multipage_metadata, theme, updated_at}
>
> 2. PATCH /rest/v1/editor_published?editor_id=eq.{editor_id}      ← ⚠️ 핵심
>    {pages, title, multipage_metadata, theme, type:"multi", updated_at}
>    (editor_published row가 없으면 먼저 POST/UPSERT — 첫 publish 시)
>
> 3. PATCH /rest/v1/editor_published_metadata?editor_id=eq.{editor_id}    ← ⚠️ 핵심
>    {is_active: true}
>
> 4. POST https://www.cdbd.in/api/update-url-key
>    {editor_id, user_id, url_key}
>
> 5. POST /rest/v1/rpc/save_editor_version  {p_editor_id}
> ```
>
> - **활성화 검증**: `curl -sL https://www.cdbd.in/2account/{slug}` HTML size가 default(~152KB)가 아닌 SSR된 페이지(>180KB) + `<title>{브랜드명}</title>` 반환되면 정상.
> - **원인 추정 (검증 미완)**: 첫 `editor_published` INSERT만 한 경우 뷰어 client가 disabled state로 fallback. PATCH로 한 번 더 갱신하면 활성화. cdbd.in UI에서는 "URL 생성하기 → 저장"이 이 PATCH도 함께 처리하는 듯.
> - **수정 후에도 동일**: editor.pages 수정 후엔 editor_published도 같이 PATCH해야 게시 URL에 반영. 안 하면 게시본은 이전 상태 유지.
> - **상세 사례 기록**: `~/Documents/Codex/cdbd-design-service/룩북/작업 기록/쁘렝땅-CdBd-등록-인수인계.md`

### ⚠️ 「링크 연결」 = `linkButton` 키 (NOT `link`)

CdBd UI **「디자인 보드 → 디자인 탭 → 링크 연결」** 메뉴가 저장하는 키는 **`linkButton`** (block 또는 multiCard.items 안). `link.href` 키는 UI 메뉴와 binding 안 되어 무시됨 — anti-pattern.

| 링크 유형 | `linkButton` JSON |
|---|---|
| **전화** (`tel:`) | `{"type": "call", "phone": {"phone": "0261375642"}}` ← **하이픈 제거, 숫자만** |
| **URL** (외부) | `{"type": "url", "link": {"href": "https://...", "openNewTab": true}}` |
| **페이지 이동** | `{"type": "page", "link": {"href": "pageId=...", "openNewTab": false}}` |
| **이메일** | `{"type": "email", "email": "info@example.com"}` |
| **연락처 저장** | `{"type": "contact", ...}` |

적용 위치:
- **multiCard.items[].linkButton** ← 각 셀별 (예: 매장 정보 list 행 셀에 매장 전화)
- **button.linkButton** ← 버튼 카드 (예: 「공식몰 바로가기」 외부 URL)
- **image.linkButton** ← 단독 이미지 카드 링크

⚠️ button block에는 legacy `link: {href, openNewTab, underline}` 키도 같이 존재할 수 있으나, **UI 메뉴가 활용하는 표준 키는 `linkButton`**. 새로 PATCH 시 `linkButton` 사용 (legacy `link`도 빈 값으로 같이 두면 안전).

⚠️ **anti-pattern**: multiCard.items에 `link: {href: "tel:..."}` 형태로 넣으면 데이터엔 들어가지만 UI 「링크 연결」 메뉴엔 비어 보이고, 렌더링·뷰어에서 클릭도 안 됨.

### CdBd JSON 카드 spec 규칙

#### ⚠️ 핵심 원칙 — 디자인 보드 메뉴만 사용 + Figma 대비 % 계산

**모든 사이즈·여백·간격 조정은 CdBd "디자인 보드 메뉴"의 정식 옵션으로만 처리한다.** 임의 CSS 키(예: `padding: "0px 124px 0px"`로 가짜 가운데 정렬, `marginLeft/Right` 등)는 사용하지 않는다. UI에 노출된 옵션이 저장하는 JSON 키만 PATCH한다.

#### ⚠️ Figma 시각 결과 → 카드 데이터 변환 (textCase 등)

**텍스트 카드 등 텍스트 데이터는 Figma의 `characters` 값이 아니라 「시각 렌더링 결과」를 기준으로 입력한다.** Figma 텍스트는 `textCase` 속성(UPPER/LOWER/TITLE/SMALL_CAPS)으로 디자인 시 변환되어 보이지만 `characters` 필드엔 원본이 그대로 남는다. CdBd 텍스트 카드는 textCase 옵션이 없으므로 변환된 결과를 직접 text에 박아넣어야 한다.

| Figma textCase | 변환 |
|---|---|
| `ORIGINAL` | `characters` 그대로 |
| `UPPER` | `characters.upper()` 예: `"store information"` → `"STORE INFORMATION"` |
| `LOWER` | `characters.lower()` |
| `TITLE` | `characters.title()` |
| `SMALL_CAPS` | `characters.upper()` (CdBd는 small-caps 미지원 → 대문자로 대체) |

같은 원리로 `fontWeight`/`italic`/`textDecoration` 등 Figma 시각 속성은 lexical AST format 비트(`1=bold, 2=italic, 8=underline, 16=strikethrough` 등)에 반영한다. **추출 패턴**: `node.getStyledTextSegments(['textCase','fontName','fontSize','textDecoration'])` 결과의 첫 segment에서 textCase 읽기.

⚠️ **anti-pattern**: `characters` 값만 그대로 카드에 넣기 → Figma에선 대문자로 보이는데 CdBd에선 소문자로 표시되어 디자인 불일치.

**단위 규칙**:
- **이미지 카드 "크기" 메뉴만 % 단위** (페이지 폭 380px 대비)
- **그 외 모든 사이즈·여백·간격은 px 그대로** Figma 측정값 입력

**카드 크기 슬라이더 (모든 카드 공통)**:
- 가로 슬라이더: 1 = 10% (페이지 폭 대비). `style.width: "{N*10}%"`
- 세로 슬라이더: 1 = 상하 4px padding 추가. button은 `innerStyle.padding: "{N*4}px 15px"`

#### ⚠️ 그리드 정렬 원칙 — 버튼·multiCard·divider는 **width 대신 margin 사용**

**디바이스 무관 그리드 일치를 위해 px 기반 margin으로 폭 조정.** % width는 viewport 변동에 따라 다른 px로 계산되어 위 카드(multiCard 등)와 정렬이 어긋난다.

| 카드 종류 | 폭 조정 방법 |
|---|---|
| **버튼 / multiCard / divider / 텍스트** (그리드 일부) | `style.width` 미설정 (default 100%) + `style.margin: "상 LR하"` ← LR이 그리드 좌우 여백 (Figma 32) |
| **이미지 카드** (footer 로고 등 독립 요소) | `style.width: "{N*10}%"` 가능 (그리드 영향 X) |

**예시 (mg3 페이지)**:
- 버튼·multiCard·divider: `margin: "0px 32px 0px"` → 좌우 32px 고정 → 모든 디바이스에서 그리드 일치
- 로고: `width: "20%"` 가능 (footer 독립, 별도 핀 고정)

(이전 시행착오: 모든 카드에 width 8(80%) 적용 → 그리드는 맞지만 디바이스 viewport 변동에 취약. **margin LR 32px가 정답**.)

#### 가운데 정렬
- `width < 100% + margin LR 32`이면 좌측 32px부터 시작 (좌측 정렬)
- `width 100% + margin LR 32`이면 콘텐츠가 좌우 32 여백 유지하며 가운데 채움 (그리드 정렬)
- **이미지 카드 가운데 정렬 (footer logo 등)**: block 자체에 `align: "center"` 추가 (multiCard의 `align` 키와 동일 패턴 — UI 「정렬」 메뉴 매핑 추정). ⛔ shotgun 금지 — `alignment`/`horizontalAlign`/`alignSelf`/`justifySelf` 등 후보 키 동시 박지 말 것. 정렬이 안 먹으면 UI에서 직접 토글 후 GET diff로 표준 키 식별 (위 「디자인 보드 메뉴 1:1 매핑 키만 사용」 워크플로우)
- **하단 여백**: `style.margin` shorthand의 마지막 값 (예: `"0px 0px 32px"` = 하단 32px)

| Figma 측정 | CdBd 입력값 | 단위 |
|---|---|---|
| 로고 폭 68px | **18%** (68/380) | **% — 이미지 카드 크기만** |
| 좌우 여백 32px | **32** | px |
| 상단 여백 20px | **20** | px |
| 셀 간 gap 24px | **24** | px |
| 버튼 텍스트 13px | **13** | px |
| 버튼 내부여백 상하 16 / 좌우 0 | **16 / 0** | px |
| 구분선 두께 1px / 투명도 20% | **1 / 20** | px / % |

#### 카드별 디자인 보드 메뉴 → JSON 키 매핑

(UI 옵션을 임의 값으로 설정 후 editor GET으로 키 검증)

| UI 옵션 | JSON 키 (style 안) | 비고 |
|---|---|---|
| 외부여백 (상/좌우/하) | `margin` (3-value shorthand `"상 좌우 하"`) | 4-value/개별 키 무시됨 |
| 내부여백 | `padding` (3-value shorthand) | |
| 테두리 색·두께·스타일·모서리 | `borderColor`, `borderWidth`, `borderStyle`, `borderRadius` | |
| 카드 크기 — 가로 | `style.width: "{N*10}%"` ← **공통 패턴, 슬라이더 1=10%** | 모든 카드 (image/button/multiCard/divider) 동일 |
| 카드 크기 — 세로 | `innerStyle.padding: "{N*4}px 15px"` (button), 다른 카드 미확정 | 슬라이더 1=4px 상하 padding |
| **카드 가운데 정렬** | **`style.margin: "0px"` + `style.width: "{N*10}%"`** | CdBd가 width<100%면 **자동 가운데**. margin LR 설정하면 좌측 정렬됨 (방해) |
| multiCard 셀 간격 | `multiCard.gap` (px) | |
| 버튼 폰트 사이즈 | `theme.button.fontSize` + 카드별 `innerStyle.fontSize` | |
| 페이지 배경 | `theme.base.background` | |
| 하단 고정 (image) | `fixedPosition: "bottom"` (또는 `"top"`) ← **표준 단일 키** | editor 4348 (UI 직접 작성)에서 검증. 과거 shotgun(`fixed`/`pinned`/`sticky`/`isFixed`/`position`)은 잔재 — 박지 말 것 |

#### ⚠️ 버튼 height 조정 = 디자인 보드 「크기 → 세로」

**사용자가 "버튼 height/높이"를 언급하면 항상 버튼 카드 디자인 보드 → 크기 → 세로 값을 조정한다.** 자동화 키: `block.innerStyle.padding`의 세로값.

- 자동화: `block.innerStyle.padding = "{세로}px {가로}px"` (2-value, 3-value shorthand 안 됨)
- 예: `padding: "12px 15px"` → 세로 12 / 가로 15
- ⚠️ width·border-radius·border-color 등 다른 속성은 건드리지 않음
- **Figma 버튼 높이 매칭 공식**: `세로 padding = (Figma_height − text_line_height) / 2`
  - text=13×1.6=20.8 → Figma 45px → `(45−20.8)/2 ≈ 12px`
  - text=13×1.6=20.8 → Figma 53px → `(53−20.8)/2 ≈ 16px`
- 가로(`스타일 → 안쪽 좌우 여백`)는 사용자가 별도 요청 시에만 조정

#### 시행착오로 발견한 보조 패턴 (UI 메뉴가 안 받는 경우만)

##### `style.margin` — **3-value shorthand만 작동**
```js
"margin": "20px 32px 0px"  // ✅ 상 / 좌우 / 하
"margin": "0px 32px 0px 32px"  // ❌ 4-value 무시됨
"marginLeft": "32px"  // ❌ 개별 키 무시됨
```

##### 카드 디자인 → 외부여백 / 내부여백 / 테두리 → CSS 키 매핑
| UI 옵션 | JSON 키 (style 안) |
|---|---|
| 외부여백 (상/좌우/하) | `margin` (3-value shorthand) |
| 내부여백 | `padding` (3-value shorthand) |
| 테두리 색·두께·스타일 | `borderColor`, `borderWidth`, `borderStyle`, `borderRadius` |
| 모서리 둥글기 | `borderRadius` ("0px" = 사각형, "999px" = 알약) |

##### Outline 버튼 (다크모드 등)
- ❌ `innerStyle.borderWidth` (안 적용됨, 카드 디자인 키 사용해야)
- ✅ 카드 자체 `style.borderWidth`/`borderColor`/`borderStyle` 사용

##### Fill rgba
```js
"background": "rgba(255,255,255,0.05)"  // ✅ 흰색 5% 반투명 작동
```

##### 하단 고정 (footer pin) — ✅ 검증 완료, 표준 키 단일
**UI 「디자인 보드 → 디자인 → 하단 고정」 토글**이 set하는 표준 키:
```js
{"fixedPosition": "bottom"}  // 또는 "top"
```
- editor 4348 (사용자가 UI로 직접 작성한 다른 editor) 스캔 결과 — image 카드에 `fixedPosition: "top"` 단일 키만 존재
- ⛔ 과거 shotgun (`fixed`/`pinned`/`sticky`/`isFixed`/`position` 동시 true) 박지 말 것. 박혀있으면 UI 토글 OFF 시 일부 키 잔재 → 동작 불일치

##### 작은 요소 가운데 정렬 (로고 등)
- `marginLeft: "auto"`/`marginRight: "auto"` ❌ 무시
- ✅ 카드 `width: "100%"` + `padding: "0px {좌우계산값}px 0px"` (3-value)
- 예: 카드 폭 316 + 로고 68 → padding LR = (316-68)/2 = 124 → `padding: "0px 124px 0px"`

##### 2단 multiCard
```js
"multiCard": {
  "gap": 24,            // 셀 간 간격 (px)
  "align": "center",
  "ratio": 50,          // 50 = 1:1, 다른 값으로 좌:우 비율
  "items": [{...cell1}, {...cell2}]
}
```

### Figma → CdBd 자산 파이프라인

#### Figma REST API (3배 PNG 직접 다운로드 + 컨텍스트 우회)
필수: Personal Access Token (PAT) — `figd_*`. 사용자가 Figma 설정 → Security → Personal access tokens → Generate (Scope: File content Read).

```http
GET https://api.figma.com/v1/images/{file_key}?ids={node_id_1},{node_id_2}&scale=3&format=png
Header: X-Figma-Token: {PAT}
Response: {"err": null, "images": {"node_id": "https://figma-alpha-api.s3...amazonaws.com/..."}}
```
S3 URL을 `curl`로 디스크 직접 다운로드. **`use_figma.exportAsync`보다 우월** — base64 response truncation 회피.

#### Supabase Storage 업로드 — ⚠️ 반드시 「이미지 라이브러리 헬퍼」 경유

**Raw `storage/v1/object` POST + `editor.blocks` PATCH로 끝내지 말 것.** 그렇게 올린 이미지는 사용자의 「내 이미지」 라이브러리에 등록되지 않아 **이름 변경·삭제·재검색·재사용이 불가능**하다. 룩북 작업은 같은 자산(`A01`, `B`, `og` 등)을 재활용·재명명하는 경우가 많아 라이브러리 등록이 필수다. 「이미지 라이브러리 (사용자 자산 관리)」 섹션의 3-call 시퀀스를 그대로 따른다.

**필수 사용**: `~/.config/cdbd/image_library.py` — `upload_to_library()` / `upload_if_missing()` / `list_library()` / `find_in_library()` / `delete_from_library()` 함수가 3-call 시퀀스 + 중복 회피를 캡슐화. 자세한 호출 명세·entry schema는 「이미지 라이브러리」 섹션 참고.

```python
import sys, os
sys.path.insert(0, os.path.expanduser('~/.config/cdbd'))
from image_library import upload_if_missing
res = upload_if_missing('/Users/.../A01.jpg', name='A01')
# res['url'] = 카드 content/gallery 에 그대로 사용 (signed URL, 30년 유효)
```

> 저수준 raw API (참고용) — **새로 코드 짤 때 직접 호출 금지, 헬퍼 사용**:
> ```http
> POST /storage/v1/object/user_image/{user_id}/{YYYYMMDDHHMMSS}_{rand12}.{ext}  (binary, x-upsert: false)
> POST /storage/v1/object/sign/user_image/{path}  body {"expiresIn": 946080000}
> PATCH /rest/v1/image_modal?id=eq.{modal_id}  body {"images": [new_entry, ...existing], "is_saving": false}
> ```

### 자동화 작업 시 체크리스트

자동화 진입 전:
- [ ] Supabase access_token 만료(약 1시간) 확인 → 만료 시 브라우저 쿠키 재추출
- [ ] Figma PAT 만료 확인 (디자이너가 발급 시 90 days)
- [ ] 디자이너의 `/Downloads/{브랜드}/` 폴더 구조 확인 ([문서], [리소스], 시안/초안)

PATCH 적용 후 검증:
- [ ] 브라우저 reload → 시각 검증 (카드 배치, 색상, 간격, 페이지 fit)
- [ ] 페이지 580 초과 스크롤 알림 확인
- [ ] 모바일 viewport 미리보기 (CdBd 우측 상단 👁 아이콘)
- [ ] **⚠️ 페이지별 로고/헤더 면적 검증** — Figma `get_metadata`로 frame width 측정 → CdBd image 카드 `style.width %` 와 환산 일치 확인 (위 「6.5 최종 검증 체크리스트 → 로고 면적 검증 공식」). 누락·잘못 추가된 로고도 함께 확인
- [ ] **⚠️ 이미지 라이브러리 검증** — `python3 ~/.config/cdbd/image_library.py` 실행 → 이번 작업에서 올린 자산이 모두 「내 이미지」 그리드에 보이는지(이름·해상도·type) 확인. raw 업로드만 한 항목(라이브러리 미등록) 있으면 사용자가 UI에서 관리 불가 → 즉시 등록 보강
