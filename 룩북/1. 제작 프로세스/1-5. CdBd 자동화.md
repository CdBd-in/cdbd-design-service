## 2. 핵심 테이블 / RPC

### 테이블
| 테이블 | 용도 | 핵심 컬럼 |
|---|---|---|
| `editor` | 멀티페이지 본문 | id, title, theme, pages, multipage_metadata, type |
| `editor_url` | 슬러그(URL_key) | editor_id, **url_key**, created_at |
| `editor_published_metadata` | OG·제목·설명 | id, editor_id, title, description, image, is_active |
| `editor_published` | 게시된 본문 사본 | editor_id, theme, pages (publish snapshot) |
| `image_modal` | 사용자 이미지 갤러리 | id (user 단일 row), 이미지 메타 array |
| `user_url` | 사용자 URL 슬롯 | user_id, ... |
| Storage bucket `user_image` | 사용자 업로드 이미지 | path `user_image/{user_id}/{YYYYMMDDHHMMSS}_{rand12}.{png,jpg}` |
| Storage bucket `public_image` | 공용 (예: 디폴트 OG `open_graph/cdbd-og.webp`) | public |

### RPC 함수
| RPC | 호출 시점 |
|---|---|
| `refresh_editor_lock` | 에디터 편집 중 매 1-2초 (자동) |
| `extend_published_url_v2` | **URL 생성/게시 시점** ← RLS 우회용 |
| `save_editor_version` | 게시 버전 저장 |
| `get_editor_status_v2` | 상태 확인 |
| `get_editor_password` | 페이지 비밀번호 |

## 3. 핵심 워크플로우 시퀀스

### 멀티페이지 신규 생성 (단순 PATCH 수동 작업과 동일)
UI에서 "새 페이지 만들기 → 멀티페이지 BETA → 380×580 → 시작하기 → 테마 위저드" 5클릭 = `editor` 테이블 신규 row 생성. **자동화 안 함** (UI 한 번이 가장 빠름).

### 카드 등록 (`editor.pages` PATCH)
```http
PATCH /rest/v1/editor?id=eq.{editor_id}
Headers: apikey + Authorization Bearer + Content-Type: application/json
Body: {"pages": [...], "theme": {...}, "multipage_metadata": {...}}
```
`pages[0].blocks`를 새 array로 교체하면 페이지 내용 전체 변경. 응답 204.

### URL 생성·게시 (12 호출 시퀀스)
사용자 UI "URL 생성하기 → 입력 → 저장" 시 일어나는 호출 순서:

1. `POST /storage/v1/object/user_image/{user_id}/{file}.jpeg` — OG 이미지 업로드
2. `POST /storage/v1/object/sign/user_image/{user_id}/{file}.jpeg` `{"expiresIn": 946080000}` — 30년 signed URL
3. `PATCH /rest/v1/image_modal?id=eq.{modal_id}` — 사용자 갤러리 등록
4. `PATCH /rest/v1/editor_published?editor_id=eq.{editor_id}` — 기존 게시 row 갱신
5. `POST /rest/v1/editor_published_metadata?on_conflict=editor_id&select=*` — **UPSERT** (title/description/image)
6. `POST /rest/v1/rpc/get_editor_status_v2`
7. `PATCH /rest/v1/editor?id=eq.{editor_id}` — editor 메타 동기화
8. **`POST /rest/v1/rpc/extend_published_url_v2`** — **🎯 URL 생성 (editor_url INSERT는 RLS로 막힘 → 이 RPC만 가능)**
9. `POST /rest/v1/editor_published?select=*` — 게시 row 생성 (snapshot)
10. `PATCH /rest/v1/editor_published_metadata?editor_id=eq.{editor_id}` — meta 최종 동기화
11. `POST /rest/v1/rpc/save_editor_version`
12. `POST /rest/v1/rpc/get_editor_status_v2`

### 핵심 RLS 우회
- `editor_url` INSERT → 403 RLS violation (user_id 컬럼 없음)
- **해결: `extend_published_url_v2` RPC** 호출이 슬러그를 저장. 정확한 파라미터는 캡처 필요 (704B 응답).

## 5. CdBd JSON 카드 spec 규칙 (시행착오로 발견)

### `style.margin` — **3-value shorthand만 작동**
```js
"margin": "20px 32px 0px"  // ✅ 상 / 좌우 / 하
"margin": "0px 32px 0px 32px"  // ❌ 4-value 무시됨
"marginLeft": "32px"  // ❌ 개별 키 무시됨
```

### 카드 디자인 → 외부여백 / 내부여백 / 테두리 → CSS 키 매핑
| UI 옵션 | JSON 키 (style 안) |
|---|---|
| 외부여백 (상/좌우/하) | `margin` (3-value shorthand) |
| 내부여백 | `padding` (3-value shorthand) |
| 테두리 색·두께·스타일 | `borderColor`, `borderWidth`, `borderStyle`, `borderRadius` |
| 모서리 둥글기 | `borderRadius` ("0px" = 사각형, "999px" = 알약) |

### Outline 버튼 (다크모드 등)
- ❌ `innerStyle.borderWidth` (안 적용됨, 카드 디자인 키 사용해야)
- ✅ 카드 자체 `style.borderWidth`/`borderColor`/`borderStyle` 사용

### Fill rgba
```js
"background": "rgba(255,255,255,0.05)"  // ✅ 흰색 5% 반투명 작동
```

### 하단 고정 (footer pin)
다음 키들을 **모두** 설정 (어느 게 핵심인지 미확정):
```js
{"fixed": true, "pinned": true, "sticky": "bottom", "isFixed": true, "position": "bottom", "fixedPosition": "bottom"}
```

### 작은 요소 가운데 정렬 (로고 등)
- `marginLeft: "auto"`/`marginRight: "auto"` ❌ 무시
- ✅ 카드 `width: "100%"` + `padding: "0px {좌우계산값}px 0px"` (3-value)
- 예: 카드 폭 316 + 로고 68 → padding LR = (316-68)/2 = 124 → `padding: "0px 124px 0px"`

### 2단 multiCard
```js
"multiCard": {
  "gap": 24,            // 셀 간 간격 (px)
  "align": "center",
  "ratio": 50,          // 50 = 1:1, 다른 값으로 좌:우 비율
  "items": [{...cell1}, {...cell2}]
}
```

## 6. Figma → CdBd 자산 파이프라인

### Figma REST API (3배 PNG 직접 다운로드 + 컨텍스트 우회)
필수: Personal Access Token (PAT) — `figd_*`. 사용자가 Figma 설정 → Security → Personal access tokens → Generate (Scope: File content Read).

```http
GET https://api.figma.com/v1/images/{file_key}?ids={node_id_1},{node_id_2}&scale=3&format=png
Header: X-Figma-Token: {PAT}
Response: {"err": null, "images": {"node_id": "https://figma-alpha-api.s3...amazonaws.com/..."}}
```
S3 URL을 `curl`로 디스크 직접 다운로드. **`use_figma.exportAsync`보다 우월** — base64 response truncation 회피.

### Supabase Storage 업로드
```http
POST /storage/v1/object/user_image/{user_id}/{filename}.png
Headers: apikey + Authorization Bearer + Content-Type: image/png
Body: <binary>
```
파일명 패턴: `{YYYYMMDDHHMMSS}_{rand12}.png`

### Signed URL (사실상 영구)
```http
POST /storage/v1/object/sign/user_image/{user_id}/{filename}.png
Body: {"expiresIn": 946080000}  // 30년 (초)
```

## 8. 작업 시 체크리스트

자동화 진입 전:
- [ ] Supabase access_token 만료(약 1시간) 확인 → 만료 시 브라우저 쿠키 재추출
- [ ] Figma PAT 만료 확인 (디자이너가 발급 시 90 days)
- [ ] 디자이너의 `/Downloads/{브랜드}/` 폴더 구조 확인 ([문서], [리소스], 시안/초안)

PATCH 적용 후 검증:
- [ ] 브라우저 reload → 시각 검증 (카드 배치, 색상, 간격, 페이지 fit)
- [ ] 페이지 580 초과 스크롤 알림 확인
- [ ] 모바일 viewport 미리보기 (CdBd 우측 상단 👁 아이콘)

게시 직전:
- [ ] 슬러그 언더바 확인 (`-` → `_`)
- [ ] 제목·설명·OG 입력 확인 ([[1-4. CdBd 콘텐츠]] step 6)
- [ ] **사용자에게 한 번 확인** ([[1-4. CdBd 콘텐츠]] step 7)

## 9. 알려진 한계 / 회피

| 문제 | 회피 |
|---|---|
| `use_figma` 응답 truncation (3배 export base64) | Figma REST API (PAT) 사용 |
| `editor_url` INSERT 403 (RLS) | `rpc/extend_published_url_v2` 사용 |
| `style.margin` 4-value 무시 | 3-value shorthand 사용 |

| File upload (dropzone) JS 우회 | Supabase Storage 직접 POST |
